# 混合检索与重排

## 稀疏与稠密互补

BM25 等关键词检索擅长精确术语、错误码和产品型号；向量检索擅长不同措辞表达的相近意思。混合检索把两者候选合并，再统一排序。

```text
查询 → BM25 top-20 ─┐
                    ├→ 去重/融合 → 重排 top-5 → 给模型
查询 → 向量 top-20 ─┘
```

## RRF

Reciprocal Rank Fusion 按排名融合，而非直接比较不同检索器的分数。常见形式为对每个候选求和 `1/(k + rank)`；`k` 是平滑常数。若候选在两路都靠前，融合分数会更高。参数通过验证集调节。

## Reranker

重排模型同时阅读问题和候选片段，判断相关性，通常比单独 embedding 更精细，但延迟与费用更高。典型策略：便宜检索召回几十条，再重排到少数几条。

## 查询改写

把含糊的“它怎么收费？”补足为带上下文的独立问题。多查询扩展可提高召回，但也可能引入无关主题。HyDE 让模型生成假想答案再检索，适合部分语义场景；必须用离线测试证明有效。

## 冲突与版本

相似度最高不等于权威性最高。排序时考虑来源可信度、版本、生效时间和用户权限。不同文档冲突时，回答应说明冲突并优先遵循权威且有效的文档。

## 练习

设计一个含“报错代码 E104”和“如何找回账号”两类问题的数据集，对比 BM25、向量和混合检索的 Recall@5、MRR 与 P95 延迟。
