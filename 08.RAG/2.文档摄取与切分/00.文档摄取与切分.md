# 文档摄取、解析与切分

## 摄取流水线

```text
发现文件 → 校验类型/大小 → 病毒与权限检查 → 提取文本/表格/OCR
→ 清洗 → 保留结构 → 切分 → 赋元数据 → 去重 → 入库 → 记录版本
```

PDF 的阅读顺序、页眉页脚、表格、双栏和扫描页常导致提取错误。解析后抽查原文与文本对应关系；不要在乱码上直接做 embedding。

## Chunk 设计

切分单位应尽量保持语义完整：标题、段落、列表、代码块、表格行及其表头。固定字符数最简单，但可能截断结论与前提；结构化切分更稳。Overlap 可补边界信息，但过大导致重复检索与成本上升。

元数据至少包含：`document_id`、版本、标题、章节、页码/段落、来源 URL、更新时间、租户/权限标签。正文与索引应保存可回溯的稳定 ID。

## 更新与删除

文档变化后需要重新解析、切分和索引；旧向量要删除或失效，避免新旧政策同时出现。删除用户数据时同步清理原件、切片、向量、缓存和日志中的可识别内容。大批量更新先建新索引，验证后切换。

## 数据质量检查

- 文本是否为空、重复、乱码、顺序错乱。
- 标题和表格是否丢失。
- 引用位置是否能回到原文。
- 权限标签是否完整。
- 相同文档是否产生多份有效版本。

## 练习

选择一份带表格的 PDF 和一份 Markdown，分别切成 300、600、1000 字左右的片段；比较一个跨段问题能否被检索到，记录引用是否能准确定位。
