# 灰度发布与回滚

## 是什么

灰度让新版本先承接少量请求，观察质量、错误率、P95 和成本；回滚必须考虑数据库与后台任务兼容。

## 实践步骤

定义放量阶段、自动停止条件、监控面板和责任人。发布记录镜像、配置、迁移、模型及 Prompt 版本。保留可快速切回的旧版本。

## 容易错与验收

数据库破坏性迁移通常不能靠应用回滚修复；发布前要做兼容与恢复演练。
