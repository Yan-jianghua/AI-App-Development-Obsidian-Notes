# CI/CD 与部署

## 从提交到上线

```text
提交/PR → 格式与静态检查 → 单元测试 → 集成测试
→ 构建镜像 → 漏洞扫描 → 暂存环境验证 → 发布 → 监控
```

CI 自动验证每次变更；持续交付保证可随时发布；持续部署才是自动上线。流水线应快速反馈，失败时明确停在哪一步。

## 依赖与构建

固定 Python、依赖锁文件和基础镜像版本，保留构建产物与来源信息。密钥只通过 CI 平台安全变量注入；来自不可信 PR 的工作流不应获得生产凭证。

## 发布策略

- 滚动：逐批替换实例，要求新旧版本短期兼容。
- 蓝绿：两套环境切换流量，回滚快但资源成本高。
- 金丝雀：小流量观察错误率和延迟再逐步扩大。

数据库变更应与应用版本协调。先做兼容迁移再发布代码；删除旧字段留到确认没有旧实例使用后。

## 配置与环境

开发、测试、生产使用不同数据库、域名和密钥。环境差异用配置表达，避免修改代码分支。部署前校验必需变量和外部服务可用性。

## 回滚

应用回滚依赖旧镜像可用且 schema 兼容；数据库回滚可能损失数据，需事先设计向前修复或备份恢复。发布后的观察窗口要看错误率、P95、业务成功率和模型成本。

## 练习

为一个 FastAPI 项目列出 PR 检查与发布门禁；设计“新版本错误率升高”的回滚步骤，并说明数据库新增列为何要先兼容旧版本。
