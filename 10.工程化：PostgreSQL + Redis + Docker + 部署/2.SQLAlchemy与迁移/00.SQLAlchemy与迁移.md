# SQLAlchemy 与数据库迁移

## ORM 解决什么

ORM 将 Python 对象与数据库表映射，方便组织查询和关系；它不替代 SQL、事务理解或执行计划。要能读出 ORM 实际发出的 SQL。

## Session 生命周期

每个请求/任务独立会话，明确 commit、rollback 和 close。同步 Session 不能与异步驱动混用。连接池大小应按“实例数 × 每实例池大小”估算总数据库连接数。

```python
from sqlalchemy import create_engine
from sqlalchemy.orm import Session

engine = create_engine("postgresql+psycopg://user:pass@localhost/app")

with Session(engine) as session:
    with session.begin():
        session.add(note)
```

示例连接串仅用于解释结构；真实密码来自受保护配置。

## 迁移工作流

修改模型后生成迁移草稿，人工检查 DDL、索引、数据回填和回滚，再在测试库运行。生产迁移应考虑在线兼容：先扩展 schema，部署兼容代码，回填，再收缩旧字段。

## N+1 与加载策略

查询 100 条订单后逐条加载用户，会产生 101 次查询。使用合适的预加载、批量查询或 join，并通过日志和测试断言 SQL 数量。过度 eager load 也可能产生巨大结果集，要基于访问模式决定。

## 常见错误

- 自动生成迁移后不审查，误删列或数据。
- 在请求之外复用同一个 Session。
- 捕获异常后不 rollback。
- 为追求“纯 ORM”写出低效复杂查询，不看 SQL。
