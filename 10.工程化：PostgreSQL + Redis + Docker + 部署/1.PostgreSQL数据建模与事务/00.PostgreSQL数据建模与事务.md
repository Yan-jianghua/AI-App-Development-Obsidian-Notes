# PostgreSQL 数据建模与事务

## 先建模再优化

表表示业务实体，主键标识行，外键保护关系，唯一约束保护业务不变量。列类型应表达真实含义：金额用 `numeric` 或最小货币单位整数，时间用带时区时间戳，半结构化数据才考虑 `jsonb`。

```sql
CREATE TABLE notes (
    id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    owner_id bigint NOT NULL,
    title text NOT NULL,
    content text NOT NULL DEFAULT '',
    created_at timestamptz NOT NULL DEFAULT now(),
    UNIQUE (owner_id, title)
);
CREATE INDEX notes_owner_created_idx ON notes (owner_id, created_at DESC);
```

唯一约束比“先查询再插入”更能应对并发。索引加速读但增加写入和存储成本，应围绕实际查询与 `EXPLAIN` 设计。

## 事务

事务保证一组写入要么提交、要么回滚。隔离级别影响并发读写；应用仍需处理唯一冲突、死锁和序列化失败。重试整个事务时保证外部副作用不会重复执行。

## 锁与并发

库存扣减可用条件更新：`UPDATE products SET stock = stock - 1 WHERE id = $1 AND stock > 0`，再检查影响行数。需要复杂读改写时使用行锁或乐观并发版本号。长事务会占用连接并阻碍清理，避免在事务内等待模型 API。

## 查询性能

看实际执行计划、扫描行数、索引命中、排序和 join。分页较深时优先游标方式。不要把每个请求都做全表扫描；也不要盲目为每列建索引。

## 备份

备份只有经过恢复演练才算可靠。明确 RPO（最多可丢多少数据）和 RTO（允许恢复多久），定期校验备份、恢复步骤、密钥与访问权限。
