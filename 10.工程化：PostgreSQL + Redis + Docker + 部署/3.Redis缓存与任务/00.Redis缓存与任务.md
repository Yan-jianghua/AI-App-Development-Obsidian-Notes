# Redis 缓存与任务

## 常见用途

Redis 提供低延迟键值读写，可用于缓存、限流计数、短期会话、分布式协调和队列/流。它不应默认充当所有业务数据的唯一权威库。

## Cache-aside

```text
读：查缓存 → 未命中查数据库 → 设置带 TTL 的缓存 → 返回
写：先更新数据库 → 提交成功后删除/更新缓存
```

缓存需要设计 key 命名、租户隔离、TTL、序列化版本和失效策略。热点 key 过期时可能形成缓存击穿；可加随机 TTL、互斥加载或预热。空结果也可短暂缓存，但要防缓存穿透和错误持久化。

## 一致性

数据库与缓存不是同一个事务。接受短暂不一致时，应明确最大可容忍时间；重要数据可绕过缓存或使用事件驱动失效。删除缓存失败要监控与补偿。

## 限流

固定窗口实现简单但边界突刺明显；滑动窗口或令牌桶更平滑。多实例限流需共享状态，并用原子操作避免竞争。限流键不要直接使用未经规范化的任意用户输入。

## 队列与任务

若使用 Redis 支撑任务队列，必须定义消息确认、重试、死信、幂等和可见性。Pub/Sub 不保证离线消费者收到消息；Streams/专门队列更适合可靠任务，但也需处理重复投递。

## 运维

监控内存、淘汰策略、命中率、连接数、慢命令和持久化状态。缓存服务不可用时决定降级到数据库还是拒绝请求，防止数据库被突然打爆。

## 练习

为“用户文档列表”设计缓存：写出 key、TTL、失效时机、跨租户防护和 Redis 故障时的降级策略。
