# Docker 与 Compose

## 核心概念

镜像是不可变的应用与依赖模板，容器是镜像的运行实例；卷保存容器生命周期之外的数据；网络连接服务。构建时和运行时的配置要分清。

## Python 镜像

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY app ./app
RUN useradd --create-home appuser
USER appuser
EXPOSE 8000
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

生产镜像应固定基础镜像与依赖版本、扫描漏洞、避免把 `.env` 和测试数据复制进去。镜像层会保留历史，不能在构建中先写密钥再删除。

## Compose 本地联调

```yaml
services:
  api:
    build: .
    ports: ["8000:8000"]
    environment:
      DATABASE_URL: postgresql+psycopg://app:devpass@db:5432/app
    depends_on:
      db:
        condition: service_healthy
  db:
    image: postgres:16
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: devpass
      POSTGRES_DB: app
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U app -d app"]
      interval: 5s
      retries: 5
    volumes:
      - pgdata:/var/lib/postgresql/data
volumes:
  pgdata:
```

示例密码只可用于本机练习。`depends_on` 只是启动依赖，应用仍需处理运行时数据库断线。容器中的 `localhost` 指容器本身，所以连接数据库用服务名 `db`。

## 生产要点

资源限制、健康检查、日志、优雅停机、卷备份、网络隔离和非 root 用户都要考虑。开发时挂载源码方便热更新；生产用固定镜像和只读部署更可控。

## 练习

把 FastAPI + PostgreSQL 跑在 Compose 中，重建 API 容器后确认数据库数据仍在；再故意停止数据库，观察 API 的错误与恢复行为。
