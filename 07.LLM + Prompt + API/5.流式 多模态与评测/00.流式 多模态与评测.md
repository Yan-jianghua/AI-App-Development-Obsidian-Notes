# 流式、多模态与模型评测

## 流式输出

流式传输缩短用户等待首字的时间，但总计算时间未必变短。服务端应逐事件传递文本增量、完成信号、用量与错误；客户端要处理断线、重复片段、取消和内容审核。OpenAI 的 Responses 流式接口使用事件流，具体事件类型以 [官方流式文档](https://developers.openai.com/api/docs/guides/streaming-responses) 为准。

## 多模态输入

图片、音频、视频和文档各有不同的大小、格式、成本与隐私边界。图片理解不等于 OCR 精确提取；音频转写有说话人、噪声和时间戳问题；PDF 可能是扫描件，先判断是否有可提取文本。

上传流程要校验文件类型、大小、页数/时长；存储对象设过期时间，记录用户授权和删除机制。对模型输入做内容截断与脱敏。

## 评测集

把真实业务问题转成固定测试样本，每条含输入、可接受答案或评分规则、风险等级和证据。覆盖：正常、边界、缺资料、冲突资料、对抗性文本、多语言、超长输入。

| 指标 | 含义 |
|---|---|
| 任务成功率 | 用户目标是否完成 |
| 事实忠实度 | 回答是否受给定证据支持 |
| 格式合规率 | 是否满足 Schema/协议 |
| 拒答正确率 | 资料不足或不允许时是否恰当拒答 |
| P50/P95 延迟 | 典型与尾部等待时间 |
| 单次成本 | token、工具和基础设施费用 |

LLM 评委可提高评测效率，但自身也会有偏差；用人工抽检、明确量表和成对比较校准。上线后采集真实失败样本，加入回归集。

## 安全红队

测试提示注入、越权工具调用、敏感信息提取、重复执行、超额成本和拒绝服务。输入过滤只是辅助，真正边界在服务端授权、工具沙箱、预算和输出校验。

## 练习

给“邮件摘要”准备 20 条样本，分别测信息遗漏、编造、格式错误和延迟。每次改提示或模型都运行同一测试集，记录是否出现回退。
