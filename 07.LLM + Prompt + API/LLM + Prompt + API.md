## 一个生产请求的完整路径

```text
用户请求 → 身份/配额检查 → 构造可信指令和最小必要上下文
→ 模型 API（超时与预算）→ 校验输出/工具调用 → 审计与用量记录 → 返回
```

OpenAI 示例按 [官方快速入门](https://developers.openai.com/api/docs/quickstart) 和 [Responses API 文档](https://developers.openai.com/api/docs) 的现行思路编写；模型名、价格、能力与限额会变化，以运行环境和官方文档为准。

## 综合练习与验收

实现“把用户工单转成结构化摘要”的最小服务：保存 Prompt 版本、模型与采样参数；对输入长度、权限和预算做检查；调用模型后校验 JSON Schema。准备至少 20 个覆盖正常、缺字段、恶意文档、超长输入和多语言输入的样本。比较两个 Prompt 版本的格式通过率、人工正确率、P95 延迟与成本。验收时必须能重现失败样本，并说明超时、限流、拒答和工具调用失败的处理路径。
