# 结构化输出与工具调用

## 两个不同目标

结构化输出用于“让模型最终回答符合模式”，例如抽取发票字段；工具调用用于“让模型请求你的应用执行一个动作”，例如查询订单。两者都需要服务端校验，但工具调用还涉及授权和副作用。

## 结构化输出

JSON 格式正确不等于字段完整、枚举合法。定义模式，检查必填、类型、范围，并为拒答或无法抽取设计单独状态。可用 Pydantic 表达应用契约。

```python
from pydantic import BaseModel, Field

class Ticket(BaseModel):
    category: str
    order_id: str | None = None
    urgency: int = Field(ge=1, le=5)
```

实际 API 的结构化输出参数、支持的 Schema 子集和模型兼容性，以 [OpenAI 官方结构化输出文档](https://developers.openai.com/api/docs/guides/structured-outputs) 为准。

## 工具调用闭环

```text
开发者定义工具名称、描述、参数模式
→ 模型提出工具调用及参数
→ 应用校验参数、用户身份、权限、预算
→ 应用执行工具
→ 把工具结果传回模型
→ 模型生成最终答复
```

模型只是提出调用，不应该直接拥有数据库超级用户、Shell 或付款权限。写操作应设计幂等键、审计日志和人工审批；工具返回值同样是不可信输入。

## 工具设计原则

- 工具职责单一、名称清晰，参数尽量少。
- 用枚举、范围和长度约束缩小可调用面。
- 返回必要数据与稳定错误码，避免完整内部对象。
- 限制调用次数、并行度、运行时间和数据访问范围。
- 对危险动作采用“先计划/预览，再确认/执行”的两阶段流程。

## 常见错误

- 把工具调用参数当作已经验证的用户意图。
- 让模型自行决定可访问哪个租户的数据。
- 工具失败后模型编造成功结果。
- 在一轮循环中允许无限工具调用。

## 练习

设计 `get_order_status(order_id)` 和 `cancel_order(order_id)`：为后者补权限、状态约束、幂等和确认机制，并列出模型可能提出的非法参数。
