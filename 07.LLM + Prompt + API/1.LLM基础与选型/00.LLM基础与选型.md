# LLM 基础与选型

## 从预测到应用

大语言模型处理的是 token 序列，按上下文生成后续内容。它擅长语言转换、摘要、抽取、代码辅助和基于给定材料的回答；它不能自动知道企业私有数据、保证事实正确或替你执行未经连接的外部动作。

## 关键术语

- **Token**：模型处理与计费的基本单位，不等于汉字或单词。
- **上下文窗口**：一次请求可纳入的输入与输出总预算；超出需要截断、检索或摘要。
- **温度/采样**：影响输出变化程度；低温也不保证完全确定。
- **延迟**：首 token 时间和总完成时间要分别看。
- **幻觉**：生成了貌似合理但不受证据支持的内容。
- **推理模型**：可在复杂任务上投入更多计算，但通常增加延迟和成本。

## 选型矩阵

| 需求 | 优先比较 |
|---|---|
| 简单分类/抽取 | 准确率、结构化输出、单价、延迟 |
| 长文总结 | 上下文长度、引用忠实度、文件支持 |
| 代码生成 | 任务成功率、工具能力、测试通过率 |
| 实时语音 | 音频接口、端到端延迟、断线处理 |
| 企业知识问答 | 检索质量、权限控制、引用与成本 |

不要只看公开榜单。建立 30—100 条与自身业务相近的测试样本，记录正确率、拒答率、P95 延迟、单次成本和失败类型，再做选择。

## 上下文管理

对话历史越长，费用和噪声通常越高。保留系统约束、最近相关轮次与检索证据；旧内容可压缩为摘要，但摘要本身可能丢失事实。对于事实问答，应回到原始数据而非依赖模型“记忆”。

## 常见误区

- 把更长提示等同于更好结果；无关内容会干扰任务。
- 把模型输出当数据库记录或权威答案。
- 混淆模型训练知识与实时检索结果。
- 用单次样例比较模型质量。

## 练习

为“客服邮件分类”和“企业文档问答”分别写出质量、延迟、成本、安全的验收指标，并说明为何选型标准不同。
