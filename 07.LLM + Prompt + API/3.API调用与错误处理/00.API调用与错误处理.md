# 模型 API 调用与错误处理

## 最小 Python 示例

先安装官方 SDK，并通过环境变量提供密钥。`OPENAI_MODEL` 应配置为账户实际可用的模型；不在教材中固定某个型号。

```python
import os
from openai import OpenAI

client = OpenAI(timeout=30.0, max_retries=2)
response = client.responses.create(
    model=os.environ["OPENAI_MODEL"],
    instructions="用简洁中文回答。资料不足时明确说明。",
    input="解释什么是 HTTP 幂等性。",
)
print(response.output_text)
```

该示例是概念演示，需要真实密钥、网络和可用模型才可执行。不要把密钥硬编码、输出到日志或上传到仓库。参考：[官方快速入门](https://developers.openai.com/api/docs/quickstart)。

## 超时与重试

区分连接失败、读超时、限流、服务端错误、认证失败和请求参数错误。网络/限流/部分 5xx 可按策略重试；401、403 或校验错误应修复配置或请求。重试必须受总时限和预算约束，避免一次用户请求触发多次昂贵调用。

## 用量与成本

记录输入、输出 token、模型、业务场景、请求 ID、耗时和费用估算。对用户/租户设每日与单次上限，限制最大输出和并发。价格会变化，成本计算从实际账单和官方价格表读取，不写死在代码中。

## 会话状态

“多轮对话”需要明确状态保存方式：服务端保存完整消息、摘要，或使用 API 提供的状态机制。每条状态都应绑定用户与租户，设保留期限，支持删除。不要把别的用户上下文拼入同一次请求。

## 故障降级

- API 超时：给出可重试提示或返回已保存结果。
- 配额不足：明确提示，不无限重试。
- 模型输出无效：校验失败后有限次重试或交给人工。
- 上游不可用：触发熔断和告警，不让等待请求耗尽线程/连接。

## 练习

封装 `generate_answer(question, context)`：设置超时、总重试上限、用量记录和可区分的错误类型。用假客户端测试 429、超时、空输出和正常输出。
