# 事务、`COMMIT` 与 `ROLLBACK`

## 是什么

事务把多条修改当成一个工作单元。比如转账需要“甲减 100”和“乙加 100”一起完成；只成功一步就会造成数据错误。

## 在练习表中体验

```sql
START TRANSACTION;

UPDATE students SET age = age + 1 WHERE student_id = 1;
SELECT student_id, age FROM students WHERE student_id = 1;

ROLLBACK;
SELECT student_id, age FROM students WHERE student_id = 1;
```

事务里的第一次查询能看见当前会话刚改的值；`ROLLBACK` 后年龄恢复。若确定修改正确，用 `COMMIT` 替换 `ROLLBACK`，变更就提交。

## 容易错在哪

- MySQL 客户端一般默认开启自动提交；每条独立修改可能立刻提交。需要多步原子修改时，明确开始事务。
- `ROLLBACK` 只能撤销尚未提交且受事务支持的操作；提交后不能靠它找回数据。
- `CREATE TABLE`、`ALTER TABLE` 等 DDL 通常会触发隐式提交，别把它们当成普通可回滚修改。
- 外部操作（如发邮件）不会因为数据库 `ROLLBACK` 自动撤销。

## 记忆

> `COMMIT` = 确认保存；`ROLLBACK` = 放弃当前未提交的改动。
