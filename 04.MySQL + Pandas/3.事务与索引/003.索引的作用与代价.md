# 索引的作用与代价

## 是什么

索引像书的目录，让数据库有机会少扫描一些行。例如经常按 `scores.student_id` 查成绩，可为这一列建索引：

```sql
CREATE INDEX idx_scores_student_id ON scores (student_id);
SHOW INDEX FROM scores;
```

注意：因为练习表已有外键，InnoDB 可能已经为相关列建立可用索引。先用 `SHOW INDEX` 检查，避免重复建近似索引。

## 什么时候有帮助

常见候选是频繁用于 `WHERE`、`JOIN ON`、`ORDER BY` 的列。但“用了这些语句”不代表建索引一定快；表很小、匹配行太多、索引选择性低时，优化器可能仍选择全表扫描。

## 代价

索引占空间；新增、更新、删除行时也可能要维护索引。因此不要给每列都建索引。复合索引如 `(student_id, course)` 的顺序也重要，通常优先匹配从左开始的列组合。

## 易错观念

索引不是“让所有查询自动变快”的开关。先确定慢查询，再看执行计划和实际数据量，最后决定是否新增或调整索引。
