# ACID 与隔离级别

## ACID 用业务语言理解

| 字母 | 名称 | 直觉 |
|---|---|---|
| A | 原子性 | 一组修改全部成功或全部撤销 |
| C | 一致性 | 提交前后都满足约束和业务规则 |
| I | 隔离性 | 并发事务互相影响的程度受控制 |
| D | 持久性 | 提交成功后，系统应保存结果 |

ACID 不是说应用代码可以不检查业务规则；例如“余额不能为负”仍需通过约束或事务中的逻辑实现。

## 为什么有隔离级别

两个人同时改同一份数据，可能出现“读到别人还没提交的数据”“同一事务重复查询结果变化”等现象。隔离级别用于在并发能力与可见性之间做选择。

MySQL InnoDB 的常见隔离级别有 `READ UNCOMMITTED`、`READ COMMITTED`、`REPEATABLE READ`、`SERIALIZABLE`。默认是 `REPEATABLE READ`，但实际行为还受快照读、锁定读、语句类型影响，不能只靠四个名字判断所有并发结果。

```sql
SELECT @@transaction_isolation;
```

先查看当前会话使用的级别，再做双会话实验。初学时优先掌握：**事务边界在哪里、何时提交、并发修改是否会冲突**。
