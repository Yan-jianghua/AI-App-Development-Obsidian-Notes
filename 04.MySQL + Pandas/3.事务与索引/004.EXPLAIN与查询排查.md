# `EXPLAIN` 与查询排查

## 从执行计划开始

```sql
EXPLAIN
SELECT s.name, c.course, c.score
FROM students AS s
JOIN scores AS c ON s.student_id = c.student_id
WHERE c.student_id = 1;
```

`EXPLAIN` 展示数据库计划怎样查表，重点先看 `table`、`type`、`possible_keys`、`key`、`rows`。`key` 是计划选用的索引；`rows` 是估计检查行数，不一定等于最终结果行数。

## 排查顺序

1. 先确认 SQL 结果正确，尤其连接条件和过滤条件。
2. 看是否返回了不需要的列、处理了过多的行。
3. 用 `EXPLAIN` 看有没有异常的大量扫描、是否使用预期索引。
4. 修改索引或查询后，在真实规模且安全的测试数据上比较。

本笔记的表只有几行，看到全表扫描不一定是问题；优化器扫描小表往往更便宜。不要从这个玩具数据推断生产环境性能。

`EXPLAIN ANALYZE` 会实际执行查询以提供运行时信息。对于会改数据的语句，使用前先确认语句类型和环境；入门阶段先对只读 `SELECT` 使用。

参考：[MySQL EXPLAIN 官方说明](https://dev.mysql.com/doc/refman/8.4/en/explain.html)。
