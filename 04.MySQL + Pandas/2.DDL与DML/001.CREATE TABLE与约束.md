# `CREATE TABLE` 与约束

## 为什么需要约束

建表不只是给列起名字，还要告诉数据库哪些数据是合法的。约束能在写入时阻止错误，而不必只依赖应用代码检查。

```sql
CREATE TABLE courses (
    course_id INT PRIMARY KEY,
    course_name VARCHAR(50) NOT NULL UNIQUE,
    credits INT NOT NULL DEFAULT 1,
    CHECK (credits > 0)
);
```

| 约束 | 意思 | 若违反会怎样 |
|---|---|---|
| `PRIMARY KEY` | 每行唯一身份，且不能为空 | 重复编号或空编号失败 |
| `NOT NULL` | 必须提供值 | 插入空值失败 |
| `UNIQUE` | 该列值不得重复 | 重复课程名失败 |
| `DEFAULT` | 未提供时采用默认值 | 未写学分则用 1 |
| `CHECK` | 满足指定条件 | 非正学分失败 |
| `FOREIGN KEY` | 引用已存在的父表记录 | 不存在的学生编号失败 |

`UNIQUE` 和 `NULL` 的组合行为与主键不同；主键更适合做稳定行标识。外键例子见 [[003.练习数据与字段类型]]。

## 容易错在哪

- `DEFAULT` 只处理“没有提供该列”的情况；显式传 `NULL` 时，仍要符合 `NOT NULL`。
- 字段类型也要按业务选：金额常用 `DECIMAL`，日期用日期类型，别为了省事全部存字符串。
- 一旦数据量大，增加或修改约束可能影响现有数据，先检查旧数据是否满足新规则。
