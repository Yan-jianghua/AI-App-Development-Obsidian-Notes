# Python `unittest` 模块

> [!abstract] 概述  
> `unittest` 是 Python 标准库自带的单元测试框架，无需额外安装。  
> 它主要用于组织测试用例、执行测试、验证结果以及生成测试报告。

## 核心概念

| 概念           | 说明           |
| ------------ | ------------ |
| Test Case    | 单个测试用例       |
| Test Fixture | 测试前后的准备和清理工作 |
| Test Suite   | 多个测试用例组成的集合  |
| Test Runner  | 执行测试并输出结果    |
| Assertion    | 判断实际结果是否符合预期 |

---

## 基本结构

```
import unittest


def add(a, b):
    return a + b


class TestAdd(unittest.TestCase):

    def test_positive_numbers(self):
        self.assertEqual(add(1, 2), 3)

    def test_negative_numbers(self):
        self.assertEqual(add(-1, -2), -3)


if __name__ == "__main__":
    unittest.main()
```

> [!important] 命名规则
> 
> - 测试类需要继承 `unittest.TestCase`
> - 测试方法通常以 `test_` 开头
> - 使用断言方法检查结果
> - `unittest.main()` 会查找并运行当前文件中的测试

## 常用断言

### 相等判断

```
self.assertEqual(actual, expected)
self.assertNotEqual(actual, expected)
```

### 布尔判断

```
self.assertTrue(expression)
self.assertFalse(expression)
```

### 对象身份判断

```
self.assertIs(a, b)
self.assertIsNot(a, b)
```

### `None` 判断

```
self.assertIsNone(value)
self.assertIsNotNone(value)
```

### 成员判断

```
self.assertIn(item, container)
self.assertNotIn(item, container)
```

### 类型判断

```
self.assertIsInstance(obj, SomeClass)
self.assertNotIsInstance(obj, SomeClass)
```

### 数值大小判断

```
self.assertGreater(a, b)
self.assertGreaterEqual(a, b)
self.assertLess(a, b)
self.assertLessEqual(a, b)
```

### 浮点数判断

```
self.assertAlmostEqual(0.1 + 0.2, 0.3)
self.assertAlmostEqual(actual, expected, places=2)
```

> [!warning] 浮点数误差  
> 浮点数可能存在精度误差，因此通常使用 `assertAlmostEqual()`，不要直接使用 `assertEqual()`。

## 测试异常

### 判断异常类型

```
class TestDivision(unittest.TestCase):

    def test_divide_by_zero(self):
        with self.assertRaises(ZeroDivisionError):
            10 / 0
```

### 判断异常信息

```
with self.assertRaisesRegex(ValueError, "年龄不能为负数"):
    validate_age(-1)
```

### 获取异常对象

```
with self.assertRaises(ValueError) as context:
    int("abc")

exception = context.exception
```

## 测试夹具 Fixture

### `setUp()` 与 `tearDown()`

每个测试方法执行前后都会调用一次：

```
class TestList(unittest.TestCase):

    def setUp(self):
        self.data = [1, 2, 3]

    def tearDown(self):
        self.data.clear()

    def test_append(self):
        self.data.append(4)
        self.assertEqual(self.data, [1, 2, 3, 4])
```

执行顺序：

```
setUp()
    ↓
test_xxx()
    ↓
tearDown()
```

### `setUpClass()` 与 `tearDownClass()`

整个测试类只执行一次：

```
class TestDatabase(unittest.TestCase):

    @classmethod
    def setUpClass(cls):
        cls.connection = create_connection()

    @classmethod
    def tearDownClass(cls):
        cls.connection.close()
```

### 生命周期方法对照

|方法|执行时机|
|---|---|
|`setUp()`|每个测试方法执行前|
|`tearDown()`|每个测试方法执行后|
|`setUpClass()`|测试类开始前|
|`tearDownClass()`|测试类结束后|
|`setUpModule()`|测试模块开始前|
|`tearDownModule()`|测试模块结束后|

## 跳过测试

### 无条件跳过

```
@unittest.skip("功能尚未实现")
def test_new_feature(self):
    pass
```

### 根据条件跳过

```
import sys


@unittest.skipIf(sys.platform == "win32", "Windows 暂不支持")
def test_linux_feature(self):
    pass


@unittest.skipUnless(sys.platform == "linux", "仅在 Linux 上运行")
def test_linux_only(self):
    pass
```

### 在测试中跳过

```
def test_feature(self):
    if not feature_available():
        self.skipTest("当前环境不支持")
```

## 子测试 `subTest`

适合使用多组数据测试相同逻辑：

```
class TestEven(unittest.TestCase):

    def test_even_numbers(self):
        cases = [
            (2, True),
            (3, False),
            (4, True),
        ]

        for number, expected in cases:
            with self.subTest(number=number):
                actual = number % 2 == 0
                self.assertEqual(actual, expected)
```

> [!tip] `subTest` 的优点  
> 某一组数据失败后，其他数据仍然会继续测试，并且报告会指出具体失败的数据。

## 命令行运行

### 运行测试文件

```
python -m unittest test_example.py
```

### 显示详细结果

```
python -m unittest -v test_example.py
```

### 运行指定测试类

```
python -m unittest test_example.TestAdd
```

### 运行指定测试方法

```
python -m unittest test_example.TestAdd.test_positive_numbers
```

### 自动发现测试

```
python -m unittest discover
```

指定测试目录和文件模式：

```
python -m unittest discover -s tests -p "test_*.py"
```

参数含义：

|参数|说明|
|---|---|
|`-s`|指定测试目录|
|`-p`|指定测试文件匹配模式|
|`-v`|显示详细测试结果|

## 项目结构

```
project/
├── calculator.py
└── tests/
    ├── __init__.py
    └── test_calculator.py
```

### 被测试代码

```
# calculator.py

def divide(a, b):
    if b == 0:
        raise ValueError("除数不能为零")

    return a / b
```

### 测试代码

```
# tests/test_calculator.py

import unittest

from calculator import divide


class TestDivide(unittest.TestCase):

    def test_normal_division(self):
        self.assertEqual(divide(10, 2), 5)

    def test_zero_divisor(self):
        with self.assertRaisesRegex(ValueError, "除数不能为零"):
            divide(10, 0)


if __name__ == "__main__":
    unittest.main()
```

## 测试临时文件

推荐使用 `tempfile` 创建临时目录，避免污染真实文件：

```
import tempfile
import unittest
from pathlib import Path


class TestFile(unittest.TestCase):

    def test_write_file(self):
        with tempfile.TemporaryDirectory() as directory:
            path = Path(directory) / "data.txt"
            path.write_text("hello", encoding="utf-8")

            actual = path.read_text(encoding="utf-8")

            self.assertEqual(actual, "hello")
```

## `unittest.mock`

`unittest.mock` 用于替换测试中的外部依赖，例如：

- 网络接口
- 数据库
- 文件系统
- 系统时间
- 第三方服务

### 使用 `Mock`

```
from unittest.mock import Mock


service = Mock()
service.get_name.return_value = "小明"

result = service.get_name()

assert result == "小明"
service.get_name.assert_called_once()
```

### 使用 `patch`

```
from unittest.mock import patch


@patch("app.get_user")
def test_show_user(mock_get_user):
    mock_get_user.return_value = {"name": "小明"}

    result = show_user()

    assert result == "小明"
    mock_get_user.assert_called_once()
```

> [!warning] `patch` 路径  
> `patch()` 应指向被测试代码**实际查找对象的位置**，不一定是该对象最初定义的位置。

例如：

```
# app.py
from api import get_user
```

测试 `app.py` 时应写：

```
@patch("app.get_user")
```

而不是：

```
@patch("api.get_user")
```

## AAA 测试模式

测试代码通常可以分为三个阶段：

1. Arrange：准备测试数据
2. Act：执行被测试行为
3. Assert：验证执行结果

```
def test_student_passes(self):
    # Arrange
    score = 60

    # Act
    passed = score >= 60

    # Assert
    self.assertTrue(passed)
```

## 最佳实践

> [!success] 编写建议
> 
> - 一个测试方法尽量只验证一种行为
> - 测试之间应相互独立
> - 不要依赖测试执行顺序
> - 测试名称应清楚表达测试场景
> - 同时测试正常、边界和异常情况
> - 不要访问真实生产数据库
> - 不要调用真实付费接口
> - 使用 `setUp()` 减少重复准备代码
> - 测试失败信息应容易理解

推荐的测试方法命名：

```
def test_login_succeeds_with_correct_password(self):
    pass


def test_login_fails_with_wrong_password(self):
    pass


def test_login_fails_when_username_is_empty(self):
    pass
```

## 易错点

> [!danger] 常见问题
> 
> 1. 测试方法没有以 `test_` 开头，导致测试未被发现。
> 2. 浮点数直接使用 `assertEqual()`。
> 3. 不同测试共享并修改同一份数据。
> 4. `patch()` 的目标路径写错。
> 5. 测试依赖网络、时间或真实数据库。
> 6. 只测试正常情况，没有覆盖边界和异常情况。

## 速查模板

```
import unittest
from unittest.mock import patch


class TestSomething(unittest.TestCase):

    @classmethod
    def setUpClass(cls):
        """整个测试类开始前执行一次。"""
        pass

    def setUp(self):
        """每个测试开始前执行。"""
        pass

    def test_normal_case(self):
        """测试正常情况。"""
        actual = ...
        expected = ...

        self.assertEqual(actual, expected)

    def test_exception_case(self):
        """测试异常情况。"""
        with self.assertRaises(ValueError):
            ...

    @patch("module.dependency")
    def test_with_mock(self, mock_dependency):
        """测试外部依赖。"""
        mock_dependency.return_value = ...

        result = ...

        self.assertEqual(result, ...)

    def tearDown(self):
        """每个测试结束后执行。"""
        pass

    @classmethod
    def tearDownClass(cls):
        """整个测试类结束后执行一次。"""
        pass


if __name__ == "__main__":
    unittest.main()
```
