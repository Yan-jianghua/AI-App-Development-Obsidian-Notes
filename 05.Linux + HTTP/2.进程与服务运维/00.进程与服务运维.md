# 进程、端口、日志与服务

## 进程模型

程序是磁盘上的代码，进程是正在运行的实例。PID 标识进程，父进程可创建子进程；信号用于通知进程退出、重载或停止。

```bash
ps aux
pgrep -af uvicorn
top                         # 或 htop
kill -TERM 1234             # 请求优雅退出
kill -KILL 1234             # 无法清理资源，最后手段
```

优先发送 `TERM`，让服务器停止接收新请求、等待在途请求、关闭连接池。直接 `KILL` 可能造成临时文件、事务或消息处理状态不一致。

## 端口与监听

监听 `127.0.0.1:8000` 只接受本机访问；监听 `0.0.0.0:8000` 接受所有 IPv4 网卡的流量，但是否可达还取决于防火墙与云安全组。

```bash
ss -lntp                    # TCP监听端口与进程
lsof -i :8000               # 谁占用了8000端口
curl -v http://127.0.0.1:8000/health
```

## 环境变量与配置

```bash
export APP_ENV=production
printenv APP_ENV
```

环境变量是进程启动时继承的配置，不会自动同步到已运行进程。密钥不要写入仓库、镜像或日志；应用启动时校验必需配置并对敏感值脱敏。

## 日志

有用日志至少包含时间、级别、服务名、请求 ID、事件名和必要上下文。不要记录密码、Token、完整身份证号或用户原文。结构化 JSON 日志便于集中检索。

```bash
journalctl -u myapp.service -n 100
journalctl -u myapp.service -f
journalctl -u myapp.service --since '30 minutes ago'
```

排障时同时记录“发生了什么、从何时开始、影响多少请求、最近改了什么”。先找第一处异常，不要被后续连锁错误淹没。

## systemd 服务思路

```ini
[Unit]
Description=My FastAPI service
After=network.target

[Service]
User=appuser
WorkingDirectory=/srv/myapp
EnvironmentFile=/etc/myapp.env
ExecStart=/srv/myapp/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

修改单元文件后通常需要重新加载配置，再重启服务。生产中还应配置资源限制、健康检查、日志轮转和优雅停机时间。

## 性能观察

- CPU 高：看热点函数、死循环、序列化或模型推理。
- 内存持续上涨：看缓存无上限、连接未关闭、对象被意外引用。
- 磁盘满：看日志、临时文件、容器层和数据库。
- 请求慢但 CPU 低：常见于数据库、外部 API、锁或连接池等待。

## 练习

启动一个本地 HTTP 服务，找出它的 PID 和端口；分别正常终止与强制终止，观察日志差异。为服务设计 `/health/live` 与 `/health/ready`，说明二者为何不能完全相同。
