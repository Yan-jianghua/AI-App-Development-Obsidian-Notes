# HTTP 核心

## 请求与响应

请求由方法、目标、Header 和可选 Body 组成；响应由状态码、Header 和 Body 组成。HTTP 是无状态协议，登录状态通常由 Cookie、Token 或服务端会话补充。

```http
POST /v1/items HTTP/1.1
Host: api.example.com
Content-Type: application/json
Authorization: Bearer <token>

{"name":"book","price":19.9}
```

```http
HTTP/1.1 201 Created
Content-Type: application/json
Location: /v1/items/42

{"id":42,"name":"book","price":19.9}
```

## 方法语义

- `GET` 查询，不应改变业务状态；安全且通常幂等。
- `POST` 创建或触发动作，通常不幂等。
- `PUT` 用完整表示替换指定资源，设计上通常幂等。
- `PATCH` 部分更新，是否幂等取决于操作语义。
- `DELETE` 删除，重复执行后的目标状态可相同。

幂等表示同一请求执行一次和多次，最终服务端状态等价。支付、创建订单等操作可接受 `Idempotency-Key` 防止客户端重试造成重复副作用。

## 状态码

- `200` 成功；`201` 创建成功；`204` 成功但无响应体。
- `301/308` 永久重定向；`302/307` 临时重定向。
- `400` 请求整体有误；`401` 未认证；`403` 已识别但无权限；`404` 不存在；`409` 状态冲突；`422` 语义/校验失败；`429` 过多请求。
- `500` 未处理的服务错误；`502` 网关收到坏的上游响应；`503` 暂不可用；`504` 网关等待上游超时。

业务失败不要全部返回 `200`，也不要把所有客户端错误都变成 `500`。

## 重要 Header

- `Content-Type` 描述 Body 的媒体类型；`Accept` 表示客户端希望收到的类型。
- `Authorization` 携带凭证；日志必须脱敏。
- `Cache-Control`、`ETag`、`If-None-Match` 管理缓存与条件请求。
- `Location` 指向新资源或重定向目标。
- `X-Request-ID`/标准追踪上下文帮助跨服务关联请求。

## Cookie、缓存与内容协商

Cookie 由浏览器按域、路径、过期时间和安全属性发送。会话 Cookie 应考虑 `Secure`、`HttpOnly`、`SameSite`。私有或含用户数据的响应需谨慎缓存；`ETag` 可让未变化资源返回 `304`。

## HTTP 版本

HTTP/1.1 常见持久连接；HTTP/2 在一条连接上多路复用；HTTP/3 基于 QUIC。版本改善传输效率，但方法、状态码和大部分语义保持一致，应用正确性不能依赖“换协议自动解决”。

## curl 练习

```bash
curl -i 'https://api.example.com/items?limit=10'
curl -sS -X POST https://api.example.com/items \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer YOUR_TOKEN' \
  -d '{"name":"book"}'
```

`-i` 显示响应头，`-v` 显示连接细节，`-sS` 安静但保留错误。真实 Token 不要放进命令历史或截图。
