# 网络基础与排障

## 从域名到响应

访问 `https://api.example.com:443/v1/items` 大致经历：DNS 把域名解析为 IP；客户端与目标 IP:端口建立 TCP 连接；TLS 验证证书并协商加密；最后在连接上交换 HTTP 消息。

## 核心概念

- IP 标识网络接口，端口标识主机上的应用入口。
- `localhost`/`127.0.0.1` 指当前机器；容器里的 `localhost` 是容器自己。
- DNS 有缓存和 TTL，更换记录不会在全球同时生效。
- TCP 提供有序可靠字节流，但应用仍需设置超时、重试和幂等。
- TLS 提供传输加密、完整性和服务器身份验证；它不保证服务业务可信。

## 常用检查

```bash
getent hosts api.example.com # 使用系统解析链查询
nslookup api.example.com
ping 203.0.113.10            # ICMP被禁不代表HTTP不可用
traceroute api.example.com   # 路由路径，仅作线索
curl -v https://api.example.com/health
openssl s_client -connect api.example.com:443 -servername api.example.com
```

## 超时不是一个值

- 连接超时：无法及时建立 TCP/TLS，常见于地址、路由、防火墙或服务未监听。
- 读取超时：连上了，但服务迟迟没返回，常见于慢查询、外部依赖或过载。
- 总时限：整个业务操作允许消耗的最大时间。
- 连接池等待超时：没有可用连接，不一定是网络故障。

客户端应为每类超时设置明确上限。只有可安全重试的操作才重试，采用指数退避和随机抖动，并限制次数。

## 代理、NAT 与容器

反向代理接收公网请求，再转发给内部应用；它常负责 TLS、限流、静态文件和请求大小限制。NAT 会转换地址。容器端口映射 `8000:8000` 表示主机端口转到容器端口，应用还需在容器内监听正确网卡。

## 分层排障表

| 现象 | 优先检查 |
|---|---|
| 域名不存在 | DNS 记录、拼写、搜索域 |
| Connection refused | 服务未启动、监听地址/端口错误 |
| Connection timed out | 路由、防火墙、安全组 |
| TLS 错误 | 证书域名、有效期、证书链、系统时间 |
| 502/504 | 代理到上游失败或上游超时 |
| 401/403 | 凭证或权限，不是网络不通 |

### 一句话记忆

> 先证明域名、端口、TLS 各层是否成立，再讨论 HTTP 和业务逻辑。
