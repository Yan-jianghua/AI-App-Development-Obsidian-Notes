# `git push` 与上游分支

## 第一次推送

```bash
# 推送指定本地分支并设上游，以后可直接 git push 或 git pull。
git push -u origin main
```

- `origin`：远程名称。
- `main`：要推送的本地分支。
- `-u`：把本地 `main` 与 `origin/main` 建立上游关系。

建立后可简写：

```bash
# 把当前分支的提交推送到已配置的上游。
git push
# 从上游获取并整合到当前分支，相当于 fetch 加 merge 或 rebase。
git pull
```

## 推送功能分支

```bash
# 推送指定本地分支并设上游，以后可直接 git push 或 git pull。
git push -u origin feature/login
```

## 查看上游关系

```bash
# 列出本地分支及其上游、领先或落后信息。
git branch -vv
```

## non-fast-forward

远程分支包含本地没有的提交时，普通 push 会被拒绝。先获取并整合：

```bash
# 从远程下载提交并更新远程跟踪引用，不整合当前分支；--prune 清理失效引用，--tags 获取标签。
git fetch origin
# 将当前分支的独有提交重新应用到指定分支之后，会生成新的提交 ID。
git rebase origin/main
# 把当前分支的提交推送到已配置的上游。
git push
```

也可按团队策略使用 merge。

## 强制推送

需要更新自己已 rebase 的功能分支时，优先：

```bash
# 仅当远程仍符合本地预期时强制更新；改写共享历史前须协调。
git push --force-with-lease
```

它会在远程分支和你预期不一致时拒绝覆盖，比 `--force` 安全。共享分支和主分支不要强推。

### 一句话记忆

> 第一次 `push -u` 建立跟踪，以后才能安心简写为 `git push`。
