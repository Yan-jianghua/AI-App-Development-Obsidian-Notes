# `git push` 与上游分支

## 第一次推送

```bash
git push -u origin main
```

- `origin`：远程名称。
- `main`：要推送的本地分支。
- `-u`：把本地 `main` 与 `origin/main` 建立上游关系。

建立后可简写：

```bash
git push
git pull
```

## 推送功能分支

```bash
git push -u origin feature/login
```

## 查看上游关系

```bash
git branch -vv
```

## non-fast-forward

远程分支包含本地没有的提交时，普通 push 会被拒绝。先获取并整合：

```bash
git fetch origin
git rebase origin/main
git push
```

也可按团队策略使用 merge。

## 强制推送

需要更新自己已 rebase 的功能分支时，优先：

```bash
git push --force-with-lease
```

它会在远程分支和你预期不一致时拒绝覆盖，比 `--force` 安全。共享分支和主分支不要强推。

### 一句话记忆

> 第一次 `push -u` 建立跟踪，以后才能安心简写为 `git push`。
