# `origin` 与 `upstream`

## `origin`

克隆仓库时，Git 默认把来源远程命名为 `origin`。

如果克隆的是自己的仓库：

```text
origin → 自己的 GitHub 仓库
```

## Fork 场景中的 `upstream`

Fork 别人的项目后，常见配置：

```text
origin   → 自己 Fork 的仓库，可推送
upstream → 原项目仓库，通常只获取
```

添加原项目：

```bash
# 添加远程仓库名称及地址；origin/upstream 只是常用名称。
git remote add upstream https://github.com/ORIGINAL_OWNER/REPO.git
# 列出远程名称及拉取、推送地址；不下载内容。
git remote -v
```

同步原项目：

```bash
# 从远程下载提交并更新远程跟踪引用，不整合当前分支；--prune 清理失效引用，--tags 获取标签。
git fetch upstream
# 切换到指定已有分支；后续 merge 的接收方就是这个当前分支。
git switch main
# 仅在可快进时合并；若两边都新增提交就停止。
git merge --ff-only upstream/main
# 把指定分支或标签推到指定远程；未带 -u 时不设置上游。
git push origin main
```

远程名称都可自定义，但 `origin` 和 `upstream` 是协作中的通用约定。

### 一句话记忆

> Fork 工作流里，origin 是自己的副本，upstream 是原项目。
