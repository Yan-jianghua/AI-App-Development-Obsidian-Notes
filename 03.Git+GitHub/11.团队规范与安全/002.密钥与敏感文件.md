# 密钥与敏感文件

## 不能提交的内容

- API Key、Access Token、数据库密码。
- SSH 私钥和证书私钥。
- 真实 `.env`。
- 云服务凭据文件。
- 用户隐私和生产数据。
- 含敏感信息的日志或数据库备份。

## 正确方式

提交模板：

```dotenv
# .env.example
DATABASE_URL=
OPENAI_API_KEY=
```

忽略真实配置：

```gitignore
.env
.env.*
!.env.example
```

部署和 CI 中使用平台提供的 Secrets，而不是把值写入工作流文件。

## 已经提交怎么办

1. 立即撤销或轮换凭据。
2. 确认泄露范围和访问日志。
3. 从当前代码移除。
4. 根据仓库情况清理历史。
5. 通知协作者重新同步被改写的历史。

第一步永远是让旧密钥失效。历史清理不能保证已被看到的秘密重新安全。

## GitHub Push Protection

GitHub 可能检测受支持的秘密并阻止推送。应移除秘密并轮换，而不是为了尽快推送就直接绕过提示。

### 一句话记忆

> 密钥一旦进入提交就按已经泄露处理：先吊销，再清理。
