# 分支与提交规范

## 分支命名

```text
feature/login-api
fix/empty-password
docs/setup-guide
refactor/user-service
test/login-edge-cases
chore/update-deps
```

命名应短、明确，并能关联任务号时带上任务号：

```text
fix/123-empty-password
```

## Conventional Commits 常见类型

```text
feat: 新功能
fix: 问题修复
docs: 文档
test: 测试
refactor: 不改变外部行为的重构
perf: 性能优化
build: 构建系统或依赖
ci: CI 配置
chore: 其他维护工作
```

示例：

```text
feat(auth): 添加邮箱登录
fix(api): 空密码时返回 400
test(auth): 补充登录失败用例
```

## 原子提交

一次提交应：

- 只表达一个意图。
- 能独立理解。
- 尽量能通过测试。
- 不夹带格式化整个项目等无关变化。

“小”不等于按文件数量机械拆分，而是按逻辑目标拆分。

### 一句话记忆

> 分支说明任务，提交说明一次完整且单一的逻辑变化。
