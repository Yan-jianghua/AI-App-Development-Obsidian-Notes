# 日常协作流程

## 开始任务

```bash
# 切换到指定已有分支；后续 merge 的接收方就是这个当前分支。
git switch main
# 从远程获取并仅在可快进时更新当前分支；有分叉就停止。
git pull --ff-only
# 创建并切换到新分支；末尾若有提交或分支名，则从那里创建。
git switch -c feature/task-name
```

## 开发过程中

```bash
# 查看当前分支及工作区、暂存区状态；-s 用简短格式显示。
git status
# 比较工作区与暂存区，查看还没暂存的内容。
git diff
# 交互式按修改块暂存，适合拆分提交。
git add -p
# 比较暂存区与最新提交；--staged 和 --cached 等价。
git diff --staged
# 把已暂存内容保存为本地提交；-m 直接写说明，省略时打开编辑器。
git commit -m "feat: 完成某项功能"
```

小步提交，但每次提交应保持逻辑完整。

## 推送并创建 PR

```bash
# 推送指定本地分支并设上游，以后可直接 git push 或 git pull。
git push -u origin feature/task-name
```

在 PR 中说明问题、修改、验证方式和风险。

## 跟进主分支变化

按团队约定选择 rebase 或 merge：

```bash
# 从远程下载提交并更新远程跟踪引用，不整合当前分支；--prune 清理失效引用，--tags 获取标签。
git fetch origin
# 将当前分支的独有提交重新应用到指定分支之后，会生成新的提交 ID。
git rebase origin/main
```

如果已推送自己的分支，rebase 后通常需要：

```bash
# 仅当远程仍符合本地预期时强制更新；改写共享历史前须协调。
git push --force-with-lease
```

仅对自己的功能分支这样做。

## 合并之后

```bash
# 切换到指定已有分支；后续 merge 的接收方就是这个当前分支。
git switch main
# 从远程获取并仅在可快进时更新当前分支；有分叉就停止。
git pull --ff-only
# 删除已合并的本地分支；未合并时 Git 会拒绝。
git branch -d feature/task-name
# 从远程下载提交并更新远程跟踪引用，不整合当前分支；--prune 清理失效引用，--tags 获取标签。
git fetch --prune
```

`--prune` 清理本地已经失效的远程跟踪引用，不会删除仍存在的本地分支。

### 一句话记忆

> 从最新主线开分支，在功能分支提交，通过 PR 回到主线。
