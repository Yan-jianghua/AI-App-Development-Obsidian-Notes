# `git reset`

## 核心作用

`reset` 可以移动当前分支指针，并根据模式决定是否重置暂存区和工作区。

## 三种常用模式

### `--soft`

```bash
# 移动当前分支，保留原提交内容在暂存区。
git reset --soft HEAD~1
```

- 移动分支指针。
- 保留暂存区。
- 保留工作区。

适合撤销最近一次本地提交并重新组织提交。

### `--mixed`（默认）

```bash
# 移动当前分支并重置暂存区，保留工作区改动；--mixed 为默认模式。
git reset HEAD~1
# 移动当前分支并重置暂存区，保留工作区改动；--mixed 为默认模式。
git reset --mixed HEAD~1
```

- 移动分支指针。
- 重置暂存区。
- 保留工作区。

修改会回到未暂存状态。

### `--hard`

```bash
# 移动当前分支并重置暂存区、已跟踪文件工作区；未保存的改动会丢失。
git reset --hard HEAD~1
```

- 移动分支指针。
- 重置暂存区。
- 重置工作区。

它会丢弃已跟踪文件中的未提交修改，风险很高。

## 对比

```text
模式       HEAD       暂存区       工作区
soft       移动       保留         保留
mixed      移动       重置         保留
hard       移动       重置         重置
```

已经推送并共享的提交通常使用 `revert`，不要用 reset 改写公共历史。

### 一句话记忆

> soft 留住暂存，mixed 留住文件，hard 连文件修改也丢弃。
