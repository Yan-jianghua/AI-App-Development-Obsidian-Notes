# `git reflog`

## 作用

`reflog` 记录本地 HEAD 和分支引用移动历史。即使提交因 reset、rebase 或误删分支暂时“看不见”，仍可能通过 reflog 找回。

```bash
# 查看本地引用移动记录，寻找 reset 或 rebase 之前的提交。
git reflog
```

示例：

```text
a3f97c1 HEAD@{0}: reset: moving to HEAD~2
6bd8812 HEAD@{1}: commit: 完成支付接口
```

## 从误 reset 中恢复

先找到原提交 `6bd8812`，再创建保护分支：

```bash
# 创建指向当前提交或指定提交的分支，但不切换。
git branch recovery/payment 6bd8812
# 切换到指定已有分支；后续 merge 的接收方就是这个当前分支。
git switch recovery/payment
```

先创建新分支比直接继续 reset 更稳妥，因为它给找到的提交增加了明确引用。

## 恢复误删分支

```bash
# 查看本地引用移动记录，寻找 reset 或 rebase 之前的提交。
git reflog
# 创建指向当前提交或指定提交的分支，但不切换。
git branch restored-feature <找到的哈希>
```

## 局限

- reflog 主要是本地记录，不会随 push 上传。
- 记录会过期并可能被垃圾回收。
- 换电脑或重新 clone 后通常没有旧电脑的 reflog。

### 一句话记忆

> reflog 是本地引用的后悔药，找到提交后先建恢复分支。
