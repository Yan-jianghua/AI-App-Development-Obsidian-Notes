# `git revert`

## 作用

`revert` 不删除旧提交，而是创建一个新提交，用相反修改抵消目标提交。

```text
A──B──C──R
      ↑  ↑
   错误提交  撤销提交
```

## 撤销普通提交

```bash
# 新建一个提交来抵消目标提交，保留原历史，适合已共享的提交。
git revert <提交哈希>
```

Git 打开编辑器确认新提交说明，完成后历史仍保留原提交和撤销动作。

不立即提交：

```bash
# 应用目标提交的反向改动，但暂不创建提交。
git revert --no-commit <提交哈希>
```

适合先检查或一起撤销多个提交，最后手动 commit。

## 为什么适合公共历史

团队成员已获取旧提交时，revert 不改变已有提交哈希，只追加新历史，协作冲突更少。

## 可能产生冲突

如果目标提交之后相同代码又被修改，Git 可能无法自动反向应用。解决冲突后：

```bash
# 把指定文件当前内容放入暂存区；后续再修改需再次 add。
git add <文件>
# 解决冲突并暂存后继续反向提交。
git revert --continue
```

放弃：

```bash
# 取消正在进行的反向提交操作。
git revert --abort
```

### 一句话记忆

> reset 改写本地历史，revert 用新提交安全抵消公共历史。
