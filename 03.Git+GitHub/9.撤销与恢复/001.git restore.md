# `git restore`

## 丢弃未暂存修改

```bash
# 用暂存区版本覆盖工作区的已跟踪文件；未暂存修改会丢失。
git restore app.py
```

把工作区中的 `app.py` 恢复成暂存区版本。未提交的修改会丢失，执行前应先看 `git diff app.py`。

恢复全部已跟踪文件：

```bash
# 用暂存区版本覆盖工作区的已跟踪文件；未暂存修改会丢失。
git restore .
```

这同样会丢弃工作区修改，影响范围更大。

## 取消暂存

```bash
# 取消暂存，保留工作区修改；与普通 restore 的覆盖方向不同。
git restore --staged app.py
```

它把暂存区恢复成 `HEAD` 中的版本，但保留工作区修改。

```text
执行前：修改已暂存
执行后：修改仍在文件里，但变成未暂存
```

## 从指定提交恢复文件

```bash
# 用指定历史提交中的文件版本写入工作区，默认不暂存。
git restore --source=HEAD~1 -- app.py
```

把旧提交中的文件内容写入当前工作区。之后仍需检查、暂存和提交。

## 未跟踪文件

`git restore` 通常不删除未跟踪文件。查看哪些文件会被清理：

```bash
# 清理未跟踪文件；-nd 只预览，-fd 才实际删除文件和目录。
git clean -nd
```

`git clean` 可能永久删除未跟踪文件，初学时不要直接使用 `-fd`。

### 一句话记忆

> restore 管文件内容；加 `--staged` 时管暂存区。
