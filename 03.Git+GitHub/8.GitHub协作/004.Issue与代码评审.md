# Issue 与代码评审

## Issue

Issue 用于记录 Bug、需求、任务和讨论。一个清晰的 Bug Issue 通常包含：

- 实际行为。
- 期望行为。
- 最小复现步骤。
- 环境与版本。
- 日志或错误信息。
- 影响范围。

## 关联 PR

PR 描述可写：

```text
Closes #123
```

合并 PR 后，对应 Issue 可自动关闭。

## 代码评审关注点

- 行为是否满足需求。
- 边界情况和错误处理是否完整。
- 是否引入安全、性能或兼容问题。
- 测试是否能证明修改有效。
- 命名和结构是否便于维护。

## 如何提出评论

指出具体行为、影响和建议：

```text
当 user 为 None 时这里会访问 user.id 并抛出异常。
建议在进入该分支前返回 404，并补一个无用户用例。
```

避免只有“这里不好”“改一下”而没有原因。

### 一句话记忆

> Issue 讲清问题，PR 交付修改，Review 验证修改是否值得合并。
