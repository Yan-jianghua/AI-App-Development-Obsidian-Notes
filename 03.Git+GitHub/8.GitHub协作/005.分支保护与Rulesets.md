# 分支保护与 Rulesets

## 作用

重要分支不应依赖每个人都记得规则。GitHub 可以通过受保护分支和 Rulesets 强制执行要求。

常见规则：

- 合并前必须创建 Pull Request。
- 必须获得指定数量的批准。
- 必须通过状态检查。
- 所有评审对话必须解决。
- 禁止强制推送和删除分支。
- 要求签名提交或线性历史。

## 为什么有了写权限仍推不上 main

如果规则要求 PR，直接执行：

```bash
# 把指定分支或标签推到指定远程；未带 -u 时不设置上游。
git push origin main
```

会被拒绝。这是仓库策略在生效，不代表认证失败。

正确流程：

```bash
# 创建并切换到新分支；末尾若有提交或分支名，则从那里创建。
git switch -c feature/my-change
# 推送指定本地分支并设上游，以后可直接 git push 或 git pull。
git push -u origin feature/my-change
```

然后创建 PR。

## Rulesets 与传统保护规则

Rulesets 能将多组规则应用于分支或标签，查看哪些规则生效也更直观。具体可用能力与仓库类型和 GitHub 套餐有关。

### 一句话记忆

> 分支保护把团队约定变成平台真正执行的规则。
