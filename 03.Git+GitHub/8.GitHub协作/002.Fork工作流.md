# Fork 工作流

## 什么是 Fork

Fork 是在自己的 GitHub 账号下创建某个仓库的副本，适合没有原仓库写权限时参与贡献。

## 标准流程

1. 在 GitHub 网页点击 Fork。
2. 克隆自己的 Fork：

```bash
# 下载远程仓库及历史；指定末尾目录名可改变本地目录，--recurse-submodules 还会拉取子模块。
git clone git@github.com:YOUR_NAME/REPO.git
# 切换终端当前目录；后续 Git 命令作用于该目录所在仓库。
cd REPO
```

3. 添加原仓库：

```bash
# 添加远程仓库名称及地址；origin/upstream 只是常用名称。
git remote add upstream https://github.com/ORIGINAL_OWNER/REPO.git
```

4. 创建功能分支：

```bash
# 创建并切换到新分支；末尾若有提交或分支名，则从那里创建。
git switch -c fix/readme-link
```

5. 提交并推送到自己的 Fork：

```bash
# 推送指定本地分支并设上游，以后可直接 git push 或 git pull。
git push -u origin fix/readme-link
```

6. 在 GitHub 创建 PR，目标是原仓库。

## 同步 Fork

```bash
# 从远程下载提交并更新远程跟踪引用，不整合当前分支；--prune 清理失效引用，--tags 获取标签。
git fetch upstream
# 切换到指定已有分支；后续 merge 的接收方就是这个当前分支。
git switch main
# 仅在可快进时合并；若两边都新增提交就停止。
git merge --ff-only upstream/main
# 把指定分支或标签推到指定远程；未带 -u 时不设置上游。
git push origin main
```

### 一句话记忆

> Fork 是自己的远程副本，PR 用来请求原项目接收修改。
