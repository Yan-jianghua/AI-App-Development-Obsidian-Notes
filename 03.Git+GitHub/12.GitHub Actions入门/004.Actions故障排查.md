# Actions 故障排查

## 排查顺序

1. 打开失败的 workflow run。
2. 找到失败 job。
3. 展开第一个失败 step。
4. 阅读命令上方和下方的完整错误。
5. 在本地尽量运行同一命令。

## 常见原因

### 找不到文件

runner 的当前目录、文件名大小写或 checkout 路径可能与本地不同。Linux runner 区分大小写。

### 找不到命令或包

每次 runner 都是新环境，必须在工作流中安装依赖，不能依赖本地电脑已安装的工具。

### 本地通过、CI 失败

检查：

- Python 或依赖版本不同。
- 时区、区域设置不同。
- 环境变量缺失。
- 测试依赖执行顺序或外部网络。
- Windows 与 Linux 路径和大小写差异。

### Workflow 不触发

检查：

- 文件是否在 `.github/workflows/`。
- YAML 是否有效。
- `on` 中的事件和分支过滤是否匹配。
- 工作流文件是否已经提交并推送。

## 重新运行不是修复

如果重跑后偶尔通过，可能是竞态条件、外部服务不稳定或时间依赖测试。应找出不稳定根因，而不是把重跑当作长期方案。

### 一句话记忆

> 从第一个失败步骤开始，比较 CI 环境与本地环境的真实差异。
