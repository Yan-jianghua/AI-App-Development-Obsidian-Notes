# `git cherry-pick`

## 作用

把某个已有提交的修改复制到当前分支，并创建一个新提交。

```text
main:    A──B──C
            \
feature:     D──E

在 main 上 cherry-pick E：
main:    A──B──C──E'
```

`E'` 内容来自 E，但父提交不同，所以哈希也不同。

## 基本用法

```bash
git switch main
git cherry-pick <提交哈希>
```

连续选择多个提交：

```bash
git cherry-pick <哈希1> <哈希2>
```

应用修改但暂不提交：

```bash
git cherry-pick --no-commit <提交哈希>
```

## 冲突处理

```bash
# 编辑文件
git add <冲突文件>
git cherry-pick --continue
```

放弃：

```bash
git cherry-pick --abort
```

## 适用场景

- 把某个独立 Bug 修复带到维护分支。
- 将误提交到错误分支的一个提交移到正确分支。
- 只需要另一个分支的少量提交，不想合并整个分支。

不要用它长期替代正常合并，否则相同修改会以不同哈希散落在多条分支，历史更难理解。

### 一句话记忆

> cherry-pick 复制一个提交的改动，不会搬走原提交。
