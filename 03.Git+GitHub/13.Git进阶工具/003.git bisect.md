# `git bisect`

## 作用

当你知道“旧版本正常、当前版本出错”，但中间有很多提交时，`bisect` 用二分查找定位第一个坏提交。

如果有 1000 个提交，逐个检查最多约 1000 次；二分查找大约只需 10 次。

## 手动流程

开始：

```bash
git bisect start
git bisect bad
git bisect good <已知正常的提交>
```

Git 会检出中间某个提交。运行测试后标记：

```bash
git bisect good
# 或
git bisect bad
```

重复测试和标记，直到 Git 找到第一个坏提交。

结束并回到原分支：

```bash
git bisect reset
```

## 自动二分

如果有能通过退出码判断结果的测试命令：

```bash
git bisect start HEAD <正常提交>
git bisect run pytest tests/test_login.py -q
git bisect reset
```

退出码 `0` 表示 good，`1` 到 `127`（`125` 除外）表示 bad，`125` 表示该提交无法测试并跳过。

## 注意

如果历史中的旧提交无法安装或测试，需要准备兼容脚本，或对无法判断的提交使用：

```bash
git bisect skip
```

### 一句话记忆

> bisect 用“正常/异常”不断折半，快速找到第一个引入问题的提交。
