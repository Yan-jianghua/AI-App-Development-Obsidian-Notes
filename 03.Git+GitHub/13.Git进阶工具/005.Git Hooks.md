# Git Hooks

## 什么是 Hook

Hook 是在特定 Git 事件发生时执行的脚本，例如提交前检查或接收推送后部署。

本地仓库示例脚本位于：

```text
.git/hooks/
```

常见 Hook：

```text
pre-commit       创建提交前
commit-msg       提交说明生成后
pre-push         推送前
post-merge       合并完成后
```

## 典型用途

- 提交前运行格式检查。
- 阻止明显包含秘密的文件。
- 校验提交说明格式。
- 推送前运行快速测试。

## 一个重要限制

`.git/hooks/` 位于 `.git` 中，默认不会被 Git 跟踪。仅在自己电脑配置 Hook，团队其他人不会自动获得。

团队可使用 pre-commit 等工具，把 Hook 配置文件提交到仓库，再由每位开发者安装；关键规则仍应在 CI 和分支保护中再次验证，因为本地 Hook 可以被跳过。

## 不要放敏感逻辑

Hook 脚本也应视为可执行代码。使用第三方 Hook 前要查看内容，不要让脚本输出或上传本地秘密。

### 一句话记忆

> Hook 提供本地快速反馈，CI 才是团队统一执行的检查。
