# 项目 Git 操作流程与每一步的作用

## 一、先理解代码保存在哪里

Git 操作主要涉及四个位置：

|位置|含义|示例|
|---|---|---|
|工作区|你正在编辑的项目文件|修改代码后尚未执行 `git add`|
|暂存区|选定的、准备放入下一次提交的改动|执行 `git add` 后|
|本地仓库|已经提交到本机 Git 历史中的版本|执行 `git commit` 后|
|远程仓库|团队共享的服务器仓库|执行 `git push` 后|

基本关系：

```
修改文件 → 工作区
             │ git add：选择本次要提交的改动
             ▼
           暂存区
             │ git commit：生成本地版本记录
             ▼
           本地仓库
             │ git push：上传本地提交
             ▼
           远程仓库
```

**保存文件、提交代码和推送代码是三个不同的动作。**

## 二、首次使用：配置身份

### 第 1 步：检查 Git 是否安装

```
# 显示 Git 版本，确认已安装。
git --version
```

**作用：** 查看当前 Git 版本，确认终端可以运行 Git。

**结果：** 输出版本号，不会修改项目文件。

### 第 2 步：设置提交者姓名

```
# 设置或读取提交作者姓名；--global 作用于当前用户，省略则作用于当前仓库。
git config --global user.name "你的姓名"
```

**作用：** 设置后续提交记录中的作者姓名。

**结果：** 默认作用于当前用户的所有仓库。

### 第 3 步：设置提交者邮箱

```
# 设置或读取提交作者邮箱；仓库级配置优先于 --global。
git config --global user.email "你的邮箱"
```

**作用：** 设置后续提交记录中的作者邮箱。

**结果：** Git 提交记录会包含此邮箱。它不是远程仓库的登录密码或认证配置。

如果当前项目需要使用不同身份，在项目目录中执行：

```
# 设置或读取提交作者姓名；--global 作用于当前用户，省略则作用于当前仓库。
git config user.name "项目使用的姓名"
# 设置或读取提交作者邮箱；仓库级配置优先于 --global。
git config user.email "项目使用的邮箱"
```

**作用：** 仅为当前仓库设置身份，覆盖全局配置。

### 第 4 步：检查配置

```
# 列出配置；--show-origin 额外显示配置来自哪个文件。
git config --list --show-origin
```

**作用：** 查看 Git 配置和对应的配置文件来源。

**结果：** 可以确认身份配置是否正确，以及配置来自全局还是当前项目。

## 三、获取项目：选择一种方式

### 方式 A：项目已经有远程仓库

#### 第 1 步：克隆仓库

```
# 下载远程仓库及历史；指定末尾目录名可改变本地目录，--recurse-submodules 还会拉取子模块。
git clone <仓库地址>
```

**作用：** 将远程仓库的代码和历史下载到本地，并自动建立名为 `origin` 的远程连接。

**结果：** 当前目录下出现项目文件夹，可以开始开发。

#### 第 2 步：进入项目目录

```
# 切换终端当前目录；后续 Git 命令作用于该目录所在仓库。
cd <项目目录>
```

**作用：** 将终端的操作位置切换到项目中。

**结果：** 后续 Git 命令将针对该项目执行。

#### 第 3 步：检查远程仓库

```
# 列出远程名称及拉取、推送地址；不下载内容。
git remote -v
```

**作用：** 查看当前仓库连接的远程地址。

**结果：** 通常显示 `origin` 的拉取地址和推送地址。

#### 第 4 步：检查当前状态

```
# 查看当前分支及工作区、暂存区状态；-s 用简短格式显示。
git status
```

**作用：** 查看当前分支，以及文件是否被修改、暂存或新增。

**结果：** 正常克隆后通常处于干净状态，没有待提交修改。

### 方式 B：本地已有代码，需要首次建立仓库

#### 第 1 步：初始化 Git

```
# 在当前目录初始化仓库；-b main 同时指定初始分支名。
git init -b main
```

**作用：** 在当前目录创建 Git 仓库，设置初始分支名称为 `main`。

**结果：** Git 开始管理这个目录，但现有文件尚未被提交。

#### 第 2 步：创建 `.gitignore`

示例内容：

```
node_modules/
dist/
*.log
.env
.env.*
!.env.example
```

**作用：** 告诉 Git 哪些未跟踪文件不应该纳入版本管理。

**结果：** 依赖目录、构建产物、日志和本地环境配置不会被常规的批量暂存操作加入。

注意：`.gitignore` 对已经被 Git 跟踪的文件不生效。

#### 第 3 步：将项目文件加入暂存区

```
# 暂存当前目录及子目录的新增、修改与删除；在子目录运行不覆盖目录外。
git add .
```

**作用：** 将当前目录及其子目录中的可跟踪改动加入暂存区。

**结果：** 文件已准备提交，但还没有生成版本记录。

#### 第 4 步：检查即将提交的内容

```
# 比较暂存区与最新提交；--staged 和 --cached 等价。
git diff --cached
```

**作用：** 查看暂存区与当前提交之间的差异；首次提交时显示准备加入的内容。

**结果：** 可以在提交前检查是否误加入密码、配置文件或无关内容。

#### 第 5 步：创建首次提交

```
# 把已暂存内容保存为本地提交；-m 直接写说明，省略时打开编辑器。
git commit -m "chore: 初始化项目"
```

**作用：** 将暂存区内容保存为一次本地提交。

**结果：** 生成提交 ID，项目有了第一个可追溯版本。

#### 第 6 步：关联空的远程仓库

```
# 添加远程仓库名称及地址；origin/upstream 只是常用名称。
git remote add origin <仓库地址>
```

**作用：** 为远程仓库地址设置别名 `origin`。

**结果：** 本地知道代码应该上传到哪里，但此时还没有上传。

#### 第 7 步：首次推送

```
# 推送指定本地分支并设上游，以后可直接 git push 或 git pull。
git push -u origin main
```

**作用：** 上传本地 `main` 分支，并建立与远程 `main` 分支的跟踪关系。

**结果：** 远程仓库获得代码和提交记录；后续通常可以直接执行 `git push`。

如果远程已有提交，优先使用克隆方式获取仓库后再加入本地代码。

## 四、开始一项新任务

### 第 1 步：检查是否存在未完成修改

```
# 查看当前分支及工作区、暂存区状态；-s 用简短格式显示。
git status
```

**作用：** 确认当前分支和未提交改动。

**结果：** 帮助判断能否直接切换分支。若有未完成修改，先提交或临时保存。

### 第 2 步：切换到主分支

```
# 切换到指定已有分支；后续 merge 的接收方就是这个当前分支。
git switch main
```

**作用：** 将当前操作分支切换到 `main`。

**结果：** 工作目录更新为主分支对应的内容。存在可能被覆盖的本地修改时，Git 通常会阻止切换。

### 第 3 步：更新主分支

```
# 从远程获取并仅在可快进时更新当前分支；有分叉就停止。
git pull --ff-only origin main
```

**作用：** 获取远程 `main` 的更新，并在可以快进时更新当前分支。

**结果：** 本地主分支跟上远程进度。如果本地和远程已经分叉，命令停止，避免自动生成合并提交。

### 第 4 步：创建并切换到功能分支

```
# 创建并切换到新分支；末尾若有提交或分支名，则从那里创建。
git switch -c feature/user-login
```

**作用：** 从当前提交创建新分支，并立即切换过去。

**结果：** 后续提交记录在功能分支中，便于单独开发和评审。

常见命名：

|分支|作用|
|---|---|
|`feature/user-login`|开发用户登录功能|
|`fix/login-validation`|修复登录校验问题|
|`hotfix/login-error`|修复线上紧急问题|
|`release/1.2.0`|准备和验证某个发布版本|

## 五、开发并提交代码

### 第 1 步：修改项目文件

使用编辑器编写代码并保存。

**作用：** 完成当前任务需要的业务改动。

**结果：** 改动存在于工作区，尚未进入 Git 提交历史。

### 第 2 步：查看哪些文件发生变化

```
# 查看当前分支及工作区、暂存区状态；-s 用简短格式显示。
git status
```

**作用：** 列出已修改、已删除、未跟踪和已暂存的文件。

**结果：** 确认本次改动范围。

### 第 3 步：查看具体修改

```
# 比较工作区与暂存区，查看还没暂存的内容。
git diff
```

**作用：** 查看已跟踪文件中尚未暂存的代码差异。

**结果：** 可以检查错误、调试代码和无关改动。未跟踪文件的内容不会显示在这里。

### 第 4 步：执行项目检查

执行项目规定的测试、格式检查和构建。

**作用：** 验证修改后的功能和项目是否正常。

**结果：** 在提交前发现问题。具体命令由项目技术栈决定。

### 第 5 步：选择本次要提交的文件

```
# 把指定文件当前内容放入暂存区；后续再修改需再次 add。
git add <文件路径>
```

**作用：** 将指定文件当前的改动加入暂存区。

**结果：** 下一次提交将包含这些暂存内容。

如果只想选择文件中的部分改动：

```
# 交互式按修改块暂存，适合拆分提交。
git add -p
```

**作用：** 按修改片段交互式选择提交内容。

如果已经确认所有改动都属于本次任务：

```
# 暂存整个仓库的新增、修改与删除；比 add . 覆盖范围更广。
git add -A
```

**作用：** 暂存整个仓库中的新增、修改和删除。

注意：暂存之后再次编辑文件，新修改需要重新执行 `git add` 才会进入本次提交。

### 第 6 步：检查暂存内容

```
# 比较暂存区与最新提交；--staged 和 --cached 等价。
git diff --cached
```

**作用：** 查看下一次提交实际会包含的内容。

**结果：** 确保本次提交完整且没有夹带无关改动。

### 第 7 步：创建本地提交

```
# 把已暂存内容保存为本地提交；-m 直接写说明，省略时打开编辑器。
git commit -m "feat: 新增用户登录功能"
```

**作用：** 把暂存区内容保存为一个带说明的版本。

**结果：** 生成本地提交；远程仓库此时仍未更新。

常用说明前缀：

|前缀|作用|
|---|---|
|`feat`|新增功能|
|`fix`|修复问题|
|`docs`|修改文档|
|`refactor`|重构代码|
|`test`|增加或修改测试|
|`chore`|项目维护|
|`ci`|修改自动检查、发布流水线|

## 六、同步其他人的代码

### 第 1 步：获取远程最新状态

```
# 从远程下载提交并更新远程跟踪引用，不整合当前分支；--prune 清理失效引用，--tags 获取标签。
git fetch origin
```

**作用：** 下载远程新提交，更新 `origin/main` 等远程跟踪引用。

**结果：** 本地能够看到远程最新进度，但当前分支和工作区不会自动合并这些改动。

### 第 2 步：将最新主分支合并到功能分支

在 `feature/user-login` 上执行：

```
# 把指定分支合入当前分支；与 switch 不同，它会改变当前分支的历史。
git merge origin/main
```

**作用：** 将主分支的最新改动整合到当前功能分支。

**结果：** 功能分支同时包含自己的开发内容和主分支更新；必要时产生合并提交，也可能出现冲突。

### 可选方式：使用变基同步

如果团队采用变基流程，可以用以下命令替代合并：

```
# 将当前分支的独有提交重新应用到指定分支之后，会生成新的提交 ID。
git rebase origin/main
```

**作用：** 将当前分支独有的提交重新应用到最新主分支上。

**结果：** 提交历史更加线性，但相关提交 ID 会变化。

合并和变基通常选择一种即可。多人共享的分支优先遵循团队约定，避免随意改写历史。

## 七、解决合并冲突

### 第 1 步：查看冲突文件

```
# 查看当前分支及工作区、暂存区状态；-s 用简短格式显示。
git status
```

**作用：** 找出哪些文件无法被 Git 自动合并。

**结果：** 输出需要手动处理的文件列表。

### 第 2 步：编辑冲突内容

文件中可能出现：

```
<<<<<<< HEAD
一侧的代码
=======
另一侧的代码
>>>>>>> origin/main
```

**作用：** 根据业务要求决定最终保留的代码，可以保留一侧，也可以重新组合。

**结果：** 冲突标记被删除，文件变为最终需要的内容。

### 第 3 步：标记文件已解决

```
# 把指定文件当前内容放入暂存区；后续再修改需再次 add。
git add <冲突文件路径>
```

**作用：** 将处理后的文件加入暂存区，告诉 Git 该文件的冲突已经解决。

**结果：** 文件不再处于未解决冲突状态。

### 第 4 步：完成当前操作

如果冲突来自合并：

```
# 解决冲突并暂存后继续完成合并。
git merge --continue
```

**作用：** 完成被冲突中断的合并。

如果冲突来自变基：

```
# 解决冲突并暂存后继续应用后续提交。
git rebase --continue
```

**作用：** 继续应用后续提交；后续提交仍可能需要再次解决冲突。

### 第 5 步：重新测试

**作用：** 确认整合后的代码逻辑正确。

**结果：** 避免代码可以合并，但功能已经出错的情况。

如果需要放弃当前操作，分别使用：

```
# 放弃正在进行的合并，尽量恢复合并前状态。
git merge --abort
```

或：

```
# 放弃本次变基，回到开始前。
git rebase --abort
```

**作用：** 取消正在进行的合并或变基。因此开始操作前应尽量保持工作区干净。

## 八、推送到远程仓库

### 第 1 步：首次推送功能分支

```
# 推送指定本地分支并设上游，以后可直接 git push 或 git pull。
git push -u origin feature/user-login
```

**作用：** 将功能分支及其提交上传到远程，并建立跟踪关系。

**结果：** 团队成员可以获取该分支，也可以据此创建代码评审请求。

### 第 2 步：后续推送

```
# 把当前分支的提交推送到已配置的上游。
git push
```

**作用：** 将当前分支新增的本地提交上传到已配置的远程分支。

**结果：** 远程分支获得最新提交。

### 如果推送被拒绝

先执行：

```
# 从远程下载提交并更新远程跟踪引用，不整合当前分支；--prune 清理失效引用，--tags 获取标签。
git fetch origin
# 显示两个引用各自独有的提交，并用左右符号标记来源。
git log --oneline --left-right HEAD...origin/feature/user-login
```

**作用：** 更新远程状态，并比较本地和远程各自独有的提交。

**结果：** 确认是否有其他人的提交需要整合。

确认需要保留远程改动后：

```
# 把指定分支合入当前分支；与 switch 不同，它会改变当前分支的历史。
git merge origin/feature/user-login
# 把当前分支的提交推送到已配置的上游。
git push
```

**作用：** 先整合远程分支，再推送完整结果。

个人分支经过约定的变基、确实需要更新远程历史时：

```
# 仅当远程仍符合本地预期时强制更新；改写共享历史前须协调。
git push --force-with-lease origin feature/user-login
```

**作用：** 在远程分支仍符合本地预期的前提下替换远程历史。

**结果：** 远程采用改写后的提交历史。执行前仍需检查远程变化，不能将它当作普通推送被拒绝时的通用解决办法。

## 九、创建评审并合并主分支

这些操作通常在 GitHub、GitLab 等代码托管平台完成。

|步骤|操作|作用|
|---|---|---|
|1|创建 PR / MR|发起将开发成果合入目标分支的请求|
|2|选择源分支和目标分支|明确把哪个分支合入哪个分支|
|3|填写改动说明和测试结果|帮助评审人理解问题、实现和验证情况|
|4|指定评审人|由其他成员检查设计、逻辑和质量|
|5|等待自动检查|验证测试、构建和其他项目要求|
|6|根据反馈修改并推送|更新当前评审请求中的代码|
|7|合并 PR / MR|将通过评审的改动正式纳入主分支|

常见合并方式：

|方式|作用及结果|
|---|---|
|Merge commit|保留原分支提交，记录合并关系|
|Squash merge|把本次开发改动整理成一个主分支提交|
|Rebase merge|将开发提交依次放入目标分支，使历史线性|

## 十、合并后清理分支

### 第 1 步：切回主分支

```
# 切换到指定已有分支；后续 merge 的接收方就是这个当前分支。
git switch main
```

**作用：** 离开已经完成任务的功能分支。

### 第 2 步：获取合并后的代码

```
# 从远程获取并仅在可快进时更新当前分支；有分叉就停止。
git pull --ff-only origin main
```

**作用：** 更新本地主分支。

**结果：** 本地获得刚刚合并的功能和其他最新提交。

### 第 3 步：删除本地功能分支

```
# 删除已合并的本地分支；未合并时 Git 会拒绝。
git branch -d feature/user-login
```

**作用：** 删除已完成的本地分支引用。

**结果：** 本地分支列表更清晰，已合入主分支的代码不会因此消失。

如果使用 Squash merge，Git 可能拒绝删除。确认 PR / MR 已合并且改动完整保留后，可以使用：

```
# 强制删除本地分支，即使未合并也会删除分支引用。
git branch -D feature/user-login
```

**作用：** 跳过已合并检查，强制删除该本地分支引用。

### 第 4 步：删除远程功能分支

```
# 删除指定远程分支或标签，不删除本地引用。
git push origin --delete feature/user-login
```

**作用：** 删除远程仓库中的功能分支。

**结果：** 团队远程分支列表得到清理。平台已自动删除时可以跳过。

### 第 5 步：清理失效的远程跟踪引用

```
# 从远程下载提交并更新远程跟踪引用，不整合当前分支；--prune 清理失效引用，--tags 获取标签。
git fetch --prune
```

**作用：** 获取远程更新，并删除本地记录中远程已经不存在的分支引用。

**结果：** 本地看到的远程分支列表与实际情况更一致；不会自动删除同名本地分支。

## 十一、临时切换任务

### 第 1 步：暂存未完成的工作

```
# 临时收起已跟踪改动；-u 还包括未跟踪文件，-m 添加说明。
git stash push -u -m "登录功能开发中"
```

**作用：** 临时保存已跟踪文件的改动和未跟踪文件，并清理这些工作区改动。

**结果：** 可以切换分支处理其他任务。被忽略的文件不包含在 `-u` 中。

### 第 2 步：切换分支处理其他工作

```
# 切换到指定已有分支；后续 merge 的接收方就是这个当前分支。
git switch main
```

**作用：** 进入另一条工作线。

### 第 3 步：返回原开发分支

```
# 切换到指定已有分支；后续 merge 的接收方就是这个当前分支。
git switch feature/user-login
```

**作用：** 回到之前的开发环境。

### 第 4 步：查看临时保存记录

```
# 列出临时保存的改动记录。
git stash list
```

**作用：** 查看已保存的工作及其编号。

### 第 5 步：恢复指定记录

```
# 恢复指定暂存记录，但保留该记录；与 pop 的删除行为不同。
git stash apply 'stash@{0}'
```

**作用：** 将指定记录的改动恢复到当前工作区。

**结果：** 可以继续开发，原暂存记录仍保留。恢复时也可能出现冲突。

### 第 6 步：确认恢复后删除记录

```
# 删除指定暂存记录，不恢复内容。
git stash drop 'stash@{0}'
```

**作用：** 删除已经不需要的临时保存记录。

暂存记录保存在本地，不会随普通推送上传到远程。

## 十二、修改、撤销与恢复

不同情况应使用不同操作，不需要按顺序全部执行。

|场景|命令|作用及结果|
|---|---|---|
|文件不该加入本次提交|`git restore --staged <文件路径>`|取消暂存，保留工作区修改|
|不要某文件未暂存的修改|`git restore <文件路径>`|将文件恢复到暂存区状态，丢弃相应未暂存修改|
|修改最近一次本地提交说明|`git commit --amend -m "新的说明"`|替换最近一次提交，提交 ID 改变|
|撤销最近一次本地提交，保留暂存内容|`git reset --soft HEAD~1`|撤回提交，改动仍在暂存区|
|撤销最近一次本地提交，保留工作区内容|`git reset --mixed HEAD~1`|撤回提交并取消暂存，文件修改保留|
|撤销已经共享的普通提交|`git revert <提交ID>`|新增一条反向提交，保留原有历史|

### 为最近一次尚未共享的提交补充文件

```
# 把指定文件当前内容放入暂存区；后续再修改需再次 add。
git add <遗漏文件路径>
# 替换最近一次提交并改变其 ID；--no-edit 保留原说明，-m 改写说明。
git commit --amend --no-edit
```

第一步：将遗漏内容加入暂存区。

第二步：用暂存内容更新最近一次提交，保留原提交说明。

**结果：** 产生新的提交 ID。已经被他人使用的提交优先通过追加提交修正。

### 找回误删分支或误回退的提交

```
# 查看本地引用移动记录，寻找 reset 或 rebase 之前的提交。
git reflog
```

**作用：** 查看本地分支和 `HEAD` 的移动记录，寻找误操作前的提交。

找到提交后：

```
# 创建并切换到新分支；末尾若有提交或分支名，则从那里创建。
git switch -c recovery/lost-work <提交ID>
```

**作用：** 在目标提交上创建恢复分支。

**结果：** 重新获得访问该提交及其历史的分支入口。它不保证找回从未提交的文件内容。

### 完全对齐远程主分支

先确认当前分支和需要保留的工作：

```
# 查看当前分支及工作区、暂存区状态；-s 用简短格式显示。
git status
# 从远程下载提交并更新远程跟踪引用，不整合当前分支；--prune 清理失效引用，--tags 获取标签。
git fetch origin
# 移动当前分支并重置暂存区、已跟踪文件工作区；未保存的改动会丢失。
git reset --hard origin/main
```

三步分别用于：

1. 检查当前所在分支及未保存改动。
    
2. 获取远程主分支的最新状态。
    
3. 将**当前分支**、暂存区和工作区对齐到 `origin/main`。
    

**结果：** 当前分支上的本地独有提交不再由该分支引用，相关未提交改动会被丢弃。执行前必须保存仍需要的内容。

### 删除未跟踪文件

```
# 清理未跟踪文件；-nd 只预览，-fd 才实际删除文件和目录。
git clean -nd
```

**作用：** 预览将被删除的未跟踪文件和目录，不实际删除。

确认预览内容后：

```
# 清理未跟踪文件；-nd 只预览，-fd 才实际删除文件和目录。
git clean -fd
```

**作用：** 实际删除这些未跟踪文件和目录。

**结果：** 文件从磁盘移除；通常无法依靠 Git 恢复。

## 十三、将某个修复提交移到另一分支

### 第 1 步：进入目标分支

```
# 切换到指定已有分支；后续 merge 的接收方就是这个当前分支。
git switch <目标分支>
```

**作用：** 确定修复最终要落在哪个分支。

### 第 2 步：应用指定提交

```
# 把指定提交的改动复制到当前分支，生成新提交。
git cherry-pick <提交ID>
```

**作用：** 将某次提交的改动应用到当前分支。

**结果：** 通常生成一个新的提交，适用于只同步特定修复的情况。

如果出现冲突，解决后执行：

```
# 把指定文件当前内容放入暂存区；后续再修改需再次 add。
git add <冲突文件路径>
# 解决冲突并暂存后继续挑选提交。
git cherry-pick --continue
```

**作用：** 标记冲突解决并完成提交应用。

如果放弃本次操作：

```
# 取消正在进行的挑选提交操作。
git cherry-pick --abort
```

**作用：** 取消当前尚未完成的提交应用过程。

## 十四、发布版本

### 第 1 步：切换并更新发布来源

```
# 切换到指定已有分支；后续 merge 的接收方就是这个当前分支。
git switch main
# 从远程获取并仅在可快进时更新当前分支；有分叉就停止。
git pull --ff-only origin main
```

**作用：** 获取准备发布的主分支代码。

### 第 2 步：确认准确提交

```
# 只查看指定文件的提交历史；-- 将路径和选项分开。
git log -1 --oneline
```

**作用：** 查看当前提交 ID 和说明。

**结果：** 明确本次发布对应哪一个版本。然后完成项目要求的发布验证。

### 第 3 步：创建版本标签

```
# 创建带说明的附注标签；末尾给提交 ID 可标记旧提交。
git tag -a v1.2.0 -m "发布 v1.2.0"
```

**作用：** 给当前提交添加带说明的版本标记。

**结果：** 后续可以通过 `v1.2.0` 准确找到此次发布的代码。

### 第 4 步：推送标签

```
# 把指定分支或标签推到指定远程；未带 -u 时不设置上游。
git push origin v1.2.0
```

**作用：** 将该标签上传到远程仓库。

**结果：** 团队和发布系统可以访问此版本。是否自动触发部署取决于流水线配置。

### 第 5 步：执行项目发布流程

生成发布说明、构建产物并部署。

**作用：** 将标记的代码版本真正交付到目标环境。

**结果：** 用户使用到新版本。创建 Git 标签本身不等于部署完成。

## 十五、线上紧急修复

### 第 1 步：获取版本信息

```
# 从远程下载提交并更新远程跟踪引用，不整合当前分支；--prune 清理失效引用，--tags 获取标签。
git fetch origin --tags
```

**作用：** 获取远程提交和标签。

### 第 2 步：从线上版本创建修复分支

```
# 创建并切换到新分支；末尾若有提交或分支名，则从那里创建。
git switch -c hotfix/login-error v1.2.0
```

**作用：** 基于线上实际运行的 `v1.2.0` 创建独立修复分支。

**结果：** 修复基于准确的线上代码，不会自动包含主分支尚未发布的新功能。

### 第 3 步：修复、测试并提交

```
# 把指定文件当前内容放入暂存区；后续再修改需再次 add。
git add <修复文件路径>
# 把已暂存内容保存为本地提交；-m 直接写说明，省略时打开编辑器。
git commit -m "fix: 修复线上登录异常"
```

**作用：** 保存已经验证的紧急修复。

### 第 4 步：推送评审

```
# 推送指定本地分支并设上游，以后可直接 git push 或 git pull。
git push -u origin hotfix/login-error
```

**作用：** 将修复共享给团队，进入评审和发布验证流程。

### 第 5 步：标记并发布修复版本

在最终经过验证的发布提交上执行：

```
# 创建带说明的附注标签；末尾给提交 ID 可标记旧提交。
git tag -a v1.2.1 -m "发布登录异常修复"
# 把指定分支或标签推到指定远程；未带 -u 时不设置上游。
git push origin v1.2.1
```

**作用：** 记录并共享新修复版本，然后按项目流程部署。

### 第 6 步：同步修复到后续开发分支

通过 PR / MR 合并修复；只需要个别提交时，可使用 `git cherry-pick`。

**作用：** 让主分支和仍维护的版本分支包含此修复。

**结果：** 避免后续发布再次带回同一个问题。

## 十六、查看历史和定位问题

|命令|作用|
|---|---|
|`git log --oneline --graph --decorate --all`|查看提交历史、分支关系和标签|
|`git show <提交ID>`|查看某次提交的说明和具体改动|
|`git log --follow -- <文件路径>`|查看文件历史，并尝试追踪重命名之前的记录|
|`git blame <文件路径>`|查看各行代码最后由哪次提交修改|
|`git diff v1.1.0 v1.2.0`|比较两个版本的最终内容差异|
|`git diff origin/main...HEAD`|查看当前分支相对与主分支共同祖先的变化|
|`git branch -vv`|查看本地分支及其远程跟踪关系|

### 二分定位引入问题的提交

```
# 开始二分定位坏提交；可同时给出坏提交与已知好提交。
git bisect start
```

**作用：** 开始一次二分排查。

```
# 标记当前或指定提交为异常，缩小故障范围。
git bisect bad
```

**作用：** 标记当前版本存在问题。

```
# 标记当前或指定提交为正常，缩小故障范围。
git bisect good <已知正常的提交ID>
```

**作用：** 指定一个正常版本，建立排查范围。

Git 切换到中间候选提交后，运行测试，再根据结果执行：

```
# 标记当前或指定提交为正常，缩小故障范围。
git bisect good
```

或：

```
# 标记当前或指定提交为异常，缩小故障范围。
git bisect bad
```

**作用：** 逐步缩小问题引入范围，直至定位到相关提交。

结束后：

```
# 结束二分定位并返回原工作位置。
git bisect reset
```

**作用：** 退出二分排查，恢复到开始前的位置。

## 十七、其他常用维护操作

|操作|命令|作用|
|---|---|---|
|查看远程地址|`git remote -v`|确认从哪里获取、向哪里推送|
|修改远程地址|`git remote set-url origin <新仓库地址>`|仓库迁移后更新本地连接|
|重命名当前分支|`git branch -m <新分支名>`|修改本地当前分支名称，不自动修改远程名称|
|停止跟踪文件|`git rm --cached <文件路径>`|在下一次提交中移除文件跟踪，但保留本地文件|
|整理最近三个提交|`git rebase -i HEAD~3`|交互式修改说明、合并或调整提交，会改写历史|
|查看标签|`git tag --list`|列出本地标签|
|查看标签内容|`git show v1.2.0`|查看标签及其对应提交|

停止跟踪文件后，需要更新 `.gitignore` 并提交，才能让仓库长期保持预期状态。

### 同时处理多个分支

```
# 在另一目录创建共享同一仓库的工作树；-b 同时新建分支。
git worktree add ../project-hotfix -b hotfix/urgent origin/main
```

**作用：** 创建一个额外工作目录和新分支，用于并行处理另一项任务。

**结果：** 原目录可以继续开发，不必频繁保存和切换分支。

```
# 列出当前仓库的所有工作树。
git worktree list
```

**作用：** 查看当前仓库的所有工作目录。

完成工作并保存改动后：

```
# 移除指定附加工作树。
git worktree remove ../project-hotfix
```

**作用：** 移除额外工作目录；对应分支不会自动删除。

### 项目使用子模块

```
# 下载远程仓库及历史；指定末尾目录名可改变本地目录，--recurse-submodules 还会拉取子模块。
git clone --recurse-submodules <仓库地址>
```

**作用：** 克隆主仓库时，一起获取项目依赖的子模块仓库。

已有仓库执行：

```
# 初始化并更新子模块；--recursive 同时处理嵌套子模块。
git submodule update --init --recursive
```

**作用：** 初始化子模块，并将其切换到主仓库记录的提交版本，包括嵌套子模块。

**结果：** 本地依赖版本与项目记录一致，不代表自动更新到子模块最新版本。

## 十八、每天最常用的一条完整流程

```
# 1. 检查当前分支和未提交修改
# 查看当前分支及工作区、暂存区状态；-s 用简短格式显示。
git status

# 2. 切换到主分支
# 切换到指定已有分支；后续 merge 的接收方就是这个当前分支。
git switch main

# 3. 获取最新主分支代码
# 从远程获取并仅在可快进时更新当前分支；有分叉就停止。
git pull --ff-only origin main

# 4. 创建并切换到自己的功能分支
# 创建并切换到新分支；末尾若有提交或分支名，则从那里创建。
git switch -c feature/user-login

# 5. 编写代码后，检查尚未暂存的修改
# 比较工作区与暂存区，查看还没暂存的内容。
git diff

# 6. 将本次需要提交的文件加入暂存区
# 把指定文件当前内容放入暂存区；后续再修改需再次 add。
git add <文件路径>

# 7. 检查下一次提交会包含什么
# 比较暂存区与最新提交；--staged 和 --cached 等价。
git diff --cached

# 8. 将暂存内容保存为本地版本
# 把已暂存内容保存为本地提交；-m 直接写说明，省略时打开编辑器。
git commit -m "feat: 新增用户登录功能"

# 9. 获取团队最新提交，不自动修改当前代码
# 从远程下载提交并更新远程跟踪引用，不整合当前分支；--prune 清理失效引用，--tags 获取标签。
git fetch origin

# 10. 将最新主分支整合到功能分支
# 把指定分支合入当前分支；与 switch 不同，它会改变当前分支的历史。
git merge origin/main

# 11. 解决可能出现的冲突，并重新运行项目测试

# 12. 上传功能分支，并建立远程跟踪关系
# 推送指定本地分支并设上游，以后可直接 git push 或 git pull。
git push -u origin feature/user-login

# 13. 在代码平台创建 PR / MR，完成评审和合并

# 14. 切回主分支
# 切换到指定已有分支；后续 merge 的接收方就是这个当前分支。
git switch main

# 15. 获取已经合并的最新代码
# 从远程获取并仅在可快进时更新当前分支；有分叉就停止。
git pull --ff-only origin main

# 16. 删除已经完成的本地功能分支
# 删除已合并的本地分支；未合并时 Git 会拒绝。
git branch -d feature/user-login

# 17. 清理本地失效的远程分支引用
# 从远程下载提交并更新远程跟踪引用，不整合当前分支；--prune 清理失效引用，--tags 获取标签。
git fetch --prune
```
