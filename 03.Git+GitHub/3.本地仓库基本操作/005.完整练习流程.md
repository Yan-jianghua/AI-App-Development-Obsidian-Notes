# 本地仓库完整练习流程

## 1. 创建练习目录

```bash
# 创建目录，属于 Shell 命令而不是 Git 子命令。
mkdir git-practice
# 切换终端当前目录；后续 Git 命令作用于该目录所在仓库。
cd git-practice
# 在当前目录初始化仓库；-b main 同时指定初始分支名。
git init -b main
```

## 2. 创建 `README.md`

```markdown
# Git Practice

这是我的 Git 练习项目。
```

## 3. 查看并暂存

```bash
# 查看当前分支及工作区、暂存区状态；-s 用简短格式显示。
git status
# 把指定文件当前内容放入暂存区；后续再修改需再次 add。
git add README.md
# 查看当前分支及工作区、暂存区状态；-s 用简短格式显示。
git status
```

观察它从 Untracked 变成 Staged。

## 4. 第一次提交

```bash
# 把已暂存内容保存为本地提交；-m 直接写说明，省略时打开编辑器。
git commit -m "docs: 添加项目说明"
```

## 5. 修改并查看差异

在 `README.md` 增加一行，然后：

```bash
# 比较工作区与暂存区，查看还没暂存的内容。
git diff
# 把指定文件当前内容放入暂存区；后续再修改需再次 add。
git add README.md
# 比较暂存区与最新提交；--staged 和 --cached 等价。
git diff --staged
# 把已暂存内容保存为本地提交；-m 直接写说明，省略时打开编辑器。
git commit -m "docs: 补充学习目标"
```

## 6. 查看历史

```bash
# 只查看指定文件的提交历史；-- 将路径和选项分开。
git log --oneline --graph --decorate
```

## 自我检查

- `git add` 后为什么普通 `git diff` 变空？
- 为什么 `git diff --staged` 能看到差异？
- `commit` 保存工作区还是暂存区？

答案：`add` 把内容复制进暂存区；普通 `diff` 比较工作区和暂存区，`--staged` 比较暂存区和最新提交；`commit` 保存暂存区。

### 一句话记忆

> 亲手观察状态变化，比死记命令更容易理解 Git。
