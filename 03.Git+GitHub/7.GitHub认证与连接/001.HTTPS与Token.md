# HTTPS 与 Personal Access Token

## HTTPS 地址

```text
https://github.com/OWNER/REPO.git
```

优点：通常能穿过严格网络环境，配置直观。

## 推荐认证方式

Git for Windows 通常包含 Git Credential Manager。首次访问时，它可能打开浏览器完成登录，并安全保存凭据。

也可以用 GitHub CLI：

```bash
gh auth login
```

## Personal Access Token

某些场景会要求 Token。终端提示 Password 时输入 Token，而不是 GitHub 网页密码。

创建 Token 时遵循：

- 优先细粒度 Token。
- 只授权需要的仓库。
- 只选择需要的权限。
- 设置合理有效期。
- 不把 Token 放进代码、笔记、截图或提交历史。

## Token 泄露

立即：

1. 在 GitHub 撤销 Token。
2. 创建新 Token。
3. 清理凭据管理器中的旧记录。
4. 如果已提交，继续清理 Git 历史并通知协作者。

只删除文件中的 Token 不够，因为旧提交仍可能包含它。

### 一句话记忆

> HTTPS 登录用凭据管理器或 Token，Token 不是网页密码的永久替代品。
