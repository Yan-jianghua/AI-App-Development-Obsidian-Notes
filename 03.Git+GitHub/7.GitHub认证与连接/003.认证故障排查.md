# GitHub 认证故障排查

## 先确认远程协议

```bash
git remote -v
```

`https://` 使用 HTTPS 认证，`git@github.com:` 使用 SSH 认证。不要按 SSH 方法排查 HTTPS 地址。

## HTTPS 常见问题

```text
Authentication failed
Support for password authentication was removed
```

检查：

- 是否错误输入网页密码。
- Git Credential Manager 中是否缓存旧凭据。
- Token 是否过期、被撤销或权限不足。
- 组织是否要求额外的 SSO 授权。

## SSH 常见问题

```text
Permission denied (publickey)
```

详细测试：

```bash
ssh -vT git@github.com
ssh-add -l
```

检查公钥是否已加到正确 GitHub 账号、私钥是否被代理加载、远程 URL 中仓库所有者是否正确。

## 有认证但仍不能推送

可能不是登录问题，而是：

- 没有仓库写权限。
- 分支保护要求通过 Pull Request。
- 推送包含被安全规则拦截的秘密。
- 远程分支领先，发生 non-fast-forward。

### 一句话记忆

> 先辨别 HTTPS 或 SSH，再区分“认证失败”和“没有写权限”。
