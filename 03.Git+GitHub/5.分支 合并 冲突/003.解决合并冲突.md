# 解决合并冲突

## 冲突为什么出现

两个分支修改同一文件的同一区域，Git 无法判断应保留哪一版：

```text
main 修改第 10 行
feature 也修改第 10 行
```

冲突不是 Git 损坏，而是需要人做业务决定。

## 冲突标记

```text
<<<<<<< HEAD
当前分支的内容
=======
被合并分支的内容
>>>>>>> feature/login
```

- `HEAD` 一侧是当前分支。
- 下方是正在合并进来的分支。

## 标准解决流程

1. 查看冲突文件：

```bash
# 查看当前分支及工作区、暂存区状态；-s 用简短格式显示。
git status
```

2. 打开文件，理解两侧意图。
3. 编辑出最终正确内容，删除全部冲突标记。
4. 运行测试或手动验证。
5. 标记已解决并提交：

```bash
# 把指定文件当前内容放入暂存区；后续再修改需再次 add。
git add <冲突文件>
# 把已暂存内容保存为本地提交；-m 直接写说明，省略时打开编辑器。
git commit
```

## 放弃本次合并

```bash
# 放弃正在进行的合并，尽量恢复合并前状态。
git merge --abort
```

## 常见错误

- 不理解代码就选择 “Accept Current” 或 “Accept Incoming”。
- 留下 `<<<<<<<` 等标记后提交。
- 只让语法通过，没有验证业务行为。
- 冲突解决过程中又混入无关重构。

可以搜索残留标记：

```bash
# 在已跟踪文件中搜索模式；-n 显示行号，多个 -e 表示任一模式。
git grep -n -e '<<<<<<<' -e '=======' -e '>>>>>>>'
```

### 一句话记忆

> 解决冲突是决定最终内容，不是机械选择其中一边。
