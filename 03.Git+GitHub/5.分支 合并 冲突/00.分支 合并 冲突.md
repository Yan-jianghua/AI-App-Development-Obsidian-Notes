## 为什么使用分支

分支让不同任务在互不影响的历史线上进行：

```text
main:       A──B─────────M
                \       /
feature:         C──D───
```

常见做法是从 `main` 创建功能分支，完成、测试和评审后再合并回 `main`。

## 基本流程

```bash
# 切换到指定已有分支；后续 merge 的接收方就是这个当前分支。
git switch main
# 从远程获取并仅在可快进时更新当前分支；有分叉就停止。
git pull --ff-only
# 创建并切换到新分支；末尾若有提交或分支名，则从那里创建。
git switch -c feature/login
# 修改、测试、提交
# 切换到指定已有分支；后续 merge 的接收方就是这个当前分支。
git switch main
# 把指定分支合入当前分支；与 switch 不同，它会改变当前分支的历史。
git merge feature/login
```

### 一句话记忆

> 一个分支处理一个目标，完成后通过合并把成果带回主线。
