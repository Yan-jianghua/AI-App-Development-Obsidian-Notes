# `git merge`

## 合并方向

要把 `feature/login` 合并进 `main`：

```bash
git switch main
git merge feature/login
```

先站在“接收修改”的分支，再合并“提供修改”的分支。

## Fast-forward 快进

如果 `main` 在创建功能分支后没有新提交：

```text
A──B main
    \
     C──D feature
```

合并只需把 `main` 指针向前移动到 D，不产生合并提交。

```text
A──B──C──D main, feature
```

## 三方合并

如果两个分支各自前进：

```text
A──B──E main
    \   \
     C──D──M
```

Git 创建合并提交 M，把两条历史连接起来。

## 常用选项

```bash
git merge --no-ff feature/login
git merge --ff-only feature/login
git merge --abort
```

- `--no-ff`：即使能快进也保留合并提交。
- `--ff-only`：不能快进时直接停止，避免意外合并提交。
- `--abort`：冲突处理中放弃本次合并，尽量回到合并前状态。

## 合并前检查

工作区应保持干净：

```bash
git status
```

未提交修改可能阻止合并，或让问题更难判断。

### 一句话记忆

> 先切到目标分支，再把来源分支 merge 进来。
