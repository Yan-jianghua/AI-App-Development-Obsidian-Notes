# `git rebase`

## 作用

`rebase` 把一组提交重新应用到新的基点上。

操作前：

```text
A──B──C main
    \
     D──E feature
```

在 `feature` 上执行：

```bash
git rebase main
```

结果：

```text
A──B──C main
       \
        D'──E' feature
```

`D'`、`E'` 是新提交，哈希不同于原来的 D、E。

## 基本流程

```bash
git switch feature/login
git rebase main
```

遇到冲突：

```bash
# 编辑并解决冲突
git add <文件>
git rebase --continue
```

其他选择：

```bash
git rebase --abort
git rebase --skip
```

`--skip` 会跳过当前提交，可能丢掉该提交的修改，必须明确知道后果。

## merge 与 rebase

```text
merge  保留分叉历史，通常新增合并提交
rebase 改写提交基点，形成线性历史
```

不要 rebase 已经推送且其他人基于其开发的公共提交，否则会让大家面对两套历史。

### 一句话记忆

> rebase 让历史更线性，但它通过重写提交实现。
