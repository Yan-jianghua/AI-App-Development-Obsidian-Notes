## 历史与差异

### git status

**`git status → 当前有哪些变化`**

> 查看当前分支及工作区、暂存区状态；-s 用简短格式显示。

### git diff

**`git diff → 具体改了什么`**

> 比较指定的两个提交或分支的文件内容。

**`git diff             # 工作区与暂存区`**

> 比较工作区与暂存区，查看还没暂存的内容。

**`git diff --staged    # 暂存区与最新提交`**

> 比较暂存区与最新提交；--staged 和 --cached 等价。

**`git diff HEAD        # 当前全部修改与最新提交`**

> 比较工作区最终内容与最新提交，包含已暂存和未暂存改动。

**`git diff HEAD~1 HEAD`**

> 比较指定的两个提交或分支的文件内容。

**`git diff main feature/login`**

> 比较指定的两个提交或分支的文件内容。

**`git diff main...feature/login`**

> 比较共同祖先到右侧分支的改动，适合看功能分支引入了什么。

**`git diff --name-status main...feature/login`**

> 只看差异文件名及新增、修改、删除状态。

**`git diff --stat`**

> 只看差异的文件与增删行数统计。

## 分支、合并与变基

### git switch

**`git switch main`**

> 切换到指定已有分支；后续 merge 的接收方就是这个当前分支。

**`git switch -c feature/login`**

> 创建并切换到新分支；末尾若有提交或分支名，则从那里创建。

**`git switch feature/login`**

> 切换到指定已有分支；后续 merge 的接收方就是这个当前分支。

**`git switch -c hotfix/login main`**

> 创建并切换到新分支；末尾若有提交或分支名，则从那里创建。

### git pull

**`git pull --ff-only`**

> 从远程获取并仅在可快进时更新当前分支；有分叉就停止。

### git merge

**`git merge feature/login`**

> 把指定分支合入当前分支；与 switch 不同，它会改变当前分支的历史。

**`git merge --no-ff feature/login`**

> 把指定分支合入当前分支，即使可快进也创建合并提交。

**`git merge --ff-only feature/login`**

> 仅在可快进时合并；若两边都新增提交就停止。

**`git merge --abort`**

> 放弃正在进行的合并，尽量恢复合并前状态。

### git branch

**`git branch`**

> 列出本地分支，并用星号标出当前分支。

**`git branch -a`**

> 列出本地及远程跟踪分支。

**`git branch -vv`**

> 列出本地分支及其上游、领先或落后信息。

**`git branch feature/login`**

> 创建指向当前提交或指定提交的分支，但不切换。

**`git branch -m feature/sign-in`**

> 重命名当前分支；不自动重命名远程分支。

**`git branch -d feature/login`**

> 删除已合并的本地分支；未合并时 Git 会拒绝。

**`git branch -D feature/login`**

> 强制删除本地分支，即使未合并也会删除分支引用。

### git status

**`git status`**

> 查看当前分支及工作区、暂存区状态；-s 用简短格式显示。

### git add

**`git add <冲突文件>`**

> 把指定文件当前内容放入暂存区；后续再修改需再次 add。

**`git add <文件>`**

> 把指定文件当前内容放入暂存区；后续再修改需再次 add。

### git commit

**`git commit`**

> 把已暂存内容保存为本地提交；-m 直接写说明，省略时打开编辑器。

### git grep

**`git grep -n -e '<<<<<<<' -e '=======' -e '>>>>>>>'`**

> 在已跟踪文件中搜索模式；-n 显示行号，多个 -e 表示任一模式。

### git rebase

**`git rebase main`**

> 将当前分支的独有提交重新应用到指定分支之后，会生成新的提交 ID。

**`git rebase --continue`**

> 解决冲突并暂存后继续应用后续提交。

**`git rebase --abort`**

> 放弃本次变基，回到开始前。

**`git rebase --skip`**

> 跳过当前提交的补丁，可能丢失该提交的改动。

## 远程仓库

### git remote

**`git remote`**

> 列出已配置的远程名称。

**`git remote -v`**

> 列出远程名称及拉取、推送地址；不下载内容。

**`git remote show origin`**

> 查看指定远程的地址、跟踪分支和推送信息。

**`git remote add origin https://github.com/OWNER/REPO.git`**

> 添加远程仓库名称及地址；origin/upstream 只是常用名称。

**`git remote set-url origin git@github.com:OWNER/REPO.git`**

> 修改已配置远程的地址，例如 HTTPS 改为 SSH。

**`git remote rename origin github`**

> 重命名本地远程配置，不会重命名 GitHub 仓库。

**`git remote remove github`**

> 删除本地远程配置，不删除远程仓库。

**`git remote add upstream https://github.com/ORIGINAL_OWNER/REPO.git`**

> 添加远程仓库名称及地址；origin/upstream 只是常用名称。

### git fetch

**`git fetch origin`**

> 从远程下载提交并更新远程跟踪引用，不整合当前分支；--prune 清理失效引用，--tags 获取标签。

**`git fetch upstream`**

> 从远程下载提交并更新远程跟踪引用，不整合当前分支；--prune 清理失效引用，--tags 获取标签。

### git log

**`git log --oneline --graph --all --decorate`**

> 只查看指定文件的提交历史；-- 将路径和选项分开。

### git diff

**`git diff main..origin/main`**

> 比较指定的两个提交或分支的文件内容。

### git pull

**`git pull = git fetch + 整合到当前分支`**

> 从上游获取并整合到当前分支，相当于 fetch 加 merge 或 rebase。

**`git pull --ff-only`**

> 从远程获取并仅在可快进时更新当前分支；有分叉就停止。

**`git pull --rebase`**

> 从远程获取后把本地提交重新应用到远程提交之后。

**`git pull`**

> 从上游获取并整合到当前分支，相当于 fetch 加 merge 或 rebase。

### git push

**`git push -u origin main`**

> 推送指定本地分支并设上游，以后可直接 git push 或 git pull。

**`git push`**

> 把当前分支的提交推送到已配置的上游。

**`git push -u origin feature/login`**

> 推送指定本地分支并设上游，以后可直接 git push 或 git pull。

**`git push --force-with-lease`**

> 仅当远程仍符合本地预期时强制更新；改写共享历史前须协调。

**`git push origin main`**

> 把指定分支或标签推到指定远程；未带 -u 时不设置上游。

### git branch

**`git branch -vv`**

> 列出本地分支及其上游、领先或落后信息。

### git rebase

**`git rebase origin/main`**

> 将当前分支的独有提交重新应用到指定分支之后，会生成新的提交 ID。

### git switch

**`git switch main`**

> 切换到指定已有分支；后续 merge 的接收方就是这个当前分支。

### git merge

**`git merge --ff-only upstream/main`**

> 仅在可快进时合并；若两边都新增提交就停止。

## GitHub 认证

### GitHub CLI

**`gh auth login`**

> 使用 GitHub CLI 交互式登录 GitHub，与设置 Git 提交作者身份不同。

### SSH 命令

**`ssh-keygen -t ed25519 -C "your_email@example.com"`**

> 生成 SSH 公钥和私钥；只把公钥添加到 GitHub，私钥留在本机。

**`ssh-add ~/.ssh/id_ed25519`**

> 把指定私钥加载到 SSH 代理，供连接 GitHub 使用。

**`ssh -T git@github.com`**

> 测试 GitHub SSH 认证是否成功，不执行远程 Shell。

**`ssh -vT git@github.com`**

> 以详细日志测试 GitHub SSH 认证，用于故障排查。

**`ssh-add -l`**

> 列出 SSH 代理中已加载的密钥。

### 终端辅助命令

**`eval "$(ssh-agent -s)"`**

> 在 Bash 中启动 SSH 代理；PowerShell 的启动方式不同。

## 撤销与恢复

### git status

**`git status`**

> 查看当前分支及工作区、暂存区状态；-s 用简短格式显示。

### git log

**`git log --oneline --decorate -10`**

> 只查看指定文件的提交历史；-- 将路径和选项分开。

### git restore

**`git restore app.py`**

> 用暂存区版本覆盖工作区的已跟踪文件；未暂存修改会丢失。

**`git restore .`**

> 用暂存区版本覆盖工作区的已跟踪文件；未暂存修改会丢失。

**`git restore --staged app.py`**

> 取消暂存，保留工作区修改；与普通 restore 的覆盖方向不同。

**`git restore --source=HEAD~1 -- app.py`**

> 用指定历史提交中的文件版本写入工作区，默认不暂存。

### git clean

**`git clean -nd`**

> 清理未跟踪文件；-nd 只预览，-fd 才实际删除文件和目录。

### git reset

**`git reset --soft HEAD~1`**

> 移动当前分支，保留原提交内容在暂存区。

**`git reset HEAD~1`**

> 移动当前分支并重置暂存区，保留工作区改动；--mixed 为默认模式。

**`git reset --mixed HEAD~1`**

> 移动当前分支并重置暂存区，保留工作区改动；--mixed 为默认模式。

**`git reset --hard HEAD~1`**

> 移动当前分支并重置暂存区、已跟踪文件工作区；未保存的改动会丢失。

### git revert

**`git revert <提交哈希>`**

> 新建一个提交来抵消目标提交，保留原历史，适合已共享的提交。

**`git revert --no-commit <提交哈希>`**

> 应用目标提交的反向改动，但暂不创建提交。

**`git revert --continue`**

> 解决冲突并暂存后继续反向提交。

**`git revert --abort`**

> 取消正在进行的反向提交操作。

### git add

**`git add <文件>`**

> 把指定文件当前内容放入暂存区；后续再修改需再次 add。

### git reflog

**`git reflog`**

> 查看本地引用移动记录，寻找 reset 或 rebase 之前的提交。

### git branch

**`git branch recovery/payment 6bd8812`**

> 创建指向当前提交或指定提交的分支，但不切换。

**`git branch restored-feature <找到的哈希>`**

### git stash

**`git stash pop`**

**`git stash drop stash@{0}`**

> 删除指定暂存记录，不恢复内容。

**`git stash clear`**

> 删除全部暂存记录，不恢复内容。

### git tag

> 创建带说明的附注标签；末尾给提交 ID 可标记旧提交。

**`git tag`**

**`git tag -l "v1.*"`**

> 按给定模式筛选本地标签。

**`git tag -d v1.0.0`**

> 删除本地标签；远程标签需另用 git push origin --delete 删除。

### git show

> 查看指定提交或标签的详情；--stat 只看统计，提交:路径可看历史文件内容。

## 相似命令的区别

| 命令 | 关键区别 |
| --- | --- |
| `git init` / `git clone` | 前者在当前目录创建新仓库；后者下载已有仓库和历史。 |
| `git add .` / `git add -A` / `git add -p` | 分别暂存当前目录范围、整个仓库、手动选择的修改块。 |
| `git diff` / `git diff --staged` / `git diff HEAD` | 分别看未暂存改动、已暂存改动、相对最新提交的全部最终改动。 |
| `git branch` / `git switch` | 前者管理分支引用；后者切换分支，`switch -c` 可创建并切换。 |
| `git merge` / `git rebase` / `git cherry-pick` | 分别合入分支历史、重放当前分支提交、只复制指定提交。 |
| `git fetch` / `git pull` / `git push` | 分别下载远程更新、下载并整合到当前分支、上传本地提交。 |
| `git restore` / `git reset` / `git revert` | 分别恢复文件或取消暂存、移动分支并重置状态、创建反向提交。 |
| `git stash apply` / `git stash pop` | 都恢复临时保存的改动；前者保留 stash 记录，后者成功后删除记录。 |
| `git tag -d` / `git push origin --delete` | 分别删除本地标签和远程标签。 |
