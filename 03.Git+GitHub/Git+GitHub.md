## 必须先掌握的最小闭环

```text
修改文件
   ↓
# 查看当前分支及工作区、暂存区状态；-s 用简短格式显示。
git status
   ↓
# 比较工作区与暂存区，查看还没暂存的内容。
git diff
   ↓
# 把指定文件当前内容放入暂存区；后续再修改需再次 add。
git add
   ↓
# 把已暂存内容保存为本地提交；-m 直接写说明，省略时打开编辑器。
git commit
   ↓
# 把当前分支的提交推送到已配置的上游。
git push
```

只要先掌握这个闭环，就能完成日常版本保存。之后再学习分支、合并、Pull Request 和撤销操作。

## 高频命令速查

```bash
# 查看当前分支及工作区、暂存区状态；-s 用简短格式显示。
git status
# 把指定文件当前内容放入暂存区；后续再修改需再次 add。
git add <文件>
# 暂存当前目录及子目录的新增、修改与删除；在子目录运行不覆盖目录外。
git add .
# 把已暂存内容保存为本地提交；-m 直接写说明，省略时打开编辑器。
git commit -m "说明"
# 只查看指定文件的提交历史；-- 将路径和选项分开。
git log --oneline --graph --all
# 创建并切换到新分支；末尾若有提交或分支名，则从那里创建。
git switch -c feature/login
# 切换到指定已有分支；后续 merge 的接收方就是这个当前分支。
git switch main
# 把指定分支合入当前分支；与 switch 不同，它会改变当前分支的历史。
git merge feature/login
# 从远程获取并仅在可快进时更新当前分支；有分叉就停止。
git pull --ff-only
# 把当前分支的提交推送到已配置的上游。
git push
```

## 学习原则

- 每次操作前先执行 `git status`。
- 撤销前先确认修改位于工作区、暂存区还是提交历史。
- 不熟悉 `reset --hard` 和强制推送时不要使用。
- 提交要小而完整，一次提交只表达一个清晰意图。
- 密钥、密码、Token 和 `.env` 文件不能提交。

### 一句话记忆

> Git 管版本，GitHub 管托管与协作；先会本地提交，再学远程协作。
