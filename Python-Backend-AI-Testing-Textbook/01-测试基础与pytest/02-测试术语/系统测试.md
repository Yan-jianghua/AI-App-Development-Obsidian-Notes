# 系统测试

## 定义

系统测试把应用作为一个完整系统进行验证，关注系统是否满足功能和非功能需求。测试者通常通过公开接口操作，而不是直接调用内部函数。

## 与集成测试的区别

集成测试关注组件连接是否正确；系统测试关注完整部署后的系统是否符合需求。两者边界在不同团队可能略有差异，关键是明确测试范围。

## 示例

文档问答系统的系统测试可以：

1. 启动 API、数据库、Redis、消息队列和向量库。
2. 创建测试租户与用户。
3. 上传文档。
4. 等待解析完成。
5. 发送问题。
6. 验证回答和引用。

它可能不经过真实浏览器，但已覆盖完整后端系统。

## 功能与非功能

系统测试除了功能，还可以验证性能、安全、恢复、兼容、容量和配置。例如系统在模型 API 超时后是否降级，而不是一直卡住。

## 测试环境

环境应尽量接近生产，包括数据库类型、配置、容器和网络边界。仍应使用测试账户和沙箱依赖，避免真实收费或外发。

## 常见错误

- 环境与生产差异过大，测试通过但上线失败。
- 一个巨大脚本覆盖几十个功能，失败难定位。
- 系统测试替代所有单元测试，反馈极慢。
- 环境数据没有重置，结果不可重复。

## 练习与面试题

练习：为“用户注册并收到欢迎邮件”设计一条系统测试，说明哪些依赖使用真实测试服务，哪些使用沙箱。
