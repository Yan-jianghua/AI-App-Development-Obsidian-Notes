# 冒烟测试

## 白话解释

冒烟测试是一组少量、快速、关键的检查，用来判断新构建或新部署“基本能不能用”。如果冒烟都失败，就没有必要继续跑数小时的完整测试。

## 例子

后端部署后的冒烟可以检查：

1. `/health` 返回成功。
2. 数据库连接正常。
3. 测试用户能登录。
4. 核心查询接口返回数据。
5. AI 模型能完成一个无副作用的最小请求。

```python
def test_health_endpoint(client):
    response = client.get("/health")
    assert response.status_code == 200
    assert response.json()["status"] == "ok"
```

## 冒烟不是什么

它不是完整回归，不覆盖所有边界；也不只是进程存活。健康接口显示 200，但数据库不可用时，真正核心功能仍可能失败。

## 运行时机

新构建完成后、部署到测试环境后、Canary 开始前、生产发布后。应在几分钟内完成。

## 设计原则

选择最关键、最便宜、最能发现环境装配失败的路径；使用专用测试数据；避免不可逆副作用。

## 常见错误

- 冒烟包含几百条用例，失去快速价值。
- 只测 `/health`，没有验证核心依赖。
- 在生产冒烟中真实发送邮件或扣款。
- 失败后仍继续扩大流量。
