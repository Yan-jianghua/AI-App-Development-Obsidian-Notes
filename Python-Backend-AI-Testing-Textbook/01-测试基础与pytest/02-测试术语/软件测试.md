# 软件测试

## 白话解释

软件测试就是用有计划的方法检查软件在不同条件下是否符合预期，并尽早暴露风险。它不只是“运行一下看看报不报错”。

## 测试不能证明什么

测试可以证明“在这些已执行条件下没有发现问题”，不能证明软件在所有可能输入和环境中永远正确。因此需要根据业务风险选择有代表性的场景。

## 测试在开发中的作用

1. 发现缺陷：例如除零崩溃、权限越权。
2. 防止回归：修改代码后旧功能仍正确。
3. 描述需求：测试清楚表达输入和结果。
4. 支持重构：只要行为未变，测试应继续通过。
5. 提供上线证据：安全、性能和质量达到门槛。

## 一个简单例子

需求：“余额不足时不能扣款。”测试不仅要验证余额充足时成功，还要验证余额相等、少 1 分、负数金额、重复请求和并发扣款。

```python
def withdraw(balance: int, amount: int) -> int:
    if amount <= 0:
        raise ValueError("amount must be positive")
    if amount > balance:
        raise ValueError("insufficient balance")
    return balance - amount
```

这里至少存在正常、非法输入和业务失败三类测试。

## 常见误解

- “代码很简单不用测”：简单条件也可能漏边界。
- “覆盖率高就没有 Bug”：覆盖只说明运行过，不说明断言有效。
- “测试是测试人员的事”：开发者最了解代码结构，应承担自动化测试。
- “最后再测试”：越晚发现缺陷，修复成本越高。
