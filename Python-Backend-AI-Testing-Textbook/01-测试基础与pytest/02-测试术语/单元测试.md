# 单元测试

## 定义

单元测试验证一个较小、明确的代码单元，例如函数、方法或领域规则，并尽量隔离数据库、网络、文件和第三方 API。

“单元”不是固定等于一行或一个函数。重点是测试范围小、失败容易定位、运行快速。

## 示例

产品代码：

```python
def calculate_discount(total: int, is_vip: bool) -> int:
    if total < 0:
        raise ValueError("total must not be negative")
    if is_vip and total >= 100:
        return int(total * 0.8)
    return total
```

测试：

```python
def test_vip_gets_discount_at_100():
    assert calculate_discount(100, True) == 80

def test_non_vip_gets_no_discount():
    assert calculate_discount(100, False) == 100
```

第一个测试如果失败，问题大概率就在折扣规则，而不是数据库或网络。

## 适合测试什么

计算、格式转换、输入校验、状态判断、权限规则、错误映射、Prompt 模板渲染等。

## 不适合单独证明什么

单元测试无法证明 SQL 在 PostgreSQL 中正确、HTTP 路由装配正确或第三方 API 契约兼容，这些需要集成测试。

## 好单元测试特征

快速、确定、独立、没有真实外部副作用、名称表达业务规则、失败原因清楚。

## 常见错误

- 把所有依赖都 Mock，测试只验证 Mock 自己。
- 绑定内部私有调用顺序，重构就失败。
- 只测正常值，不测边界和错误。

## 练习与面试题

练习：为上述折扣函数补充负数、99、100、101 和非 VIP 用例。

面试：单元测试的“单元”应该如何理解？它不能替代哪些测试？
