# 正向测试

## 定义

正向测试使用合法输入和允许状态，验证系统能完成预期业务。它回答“用户按正确方式操作时，功能能不能成功”。

## 示例

登录功能的正向用例：存在且启用的用户输入正确密码，应获得有效会话。

```python
def test_active_user_can_login():
    result = login(email="alice@example.com", password="correct")
    assert result.user.email == "alice@example.com"
    assert result.access_token
```

不能只检查“没有异常”；还应验证用户、Token、过期时间和必要副作用。

## 正向场景不只有一个

合法输入可能有多种：普通用户和管理员、最小与最大合法长度、中文和英文、不同允许格式。正向测试也应覆盖主要业务分支。

## 与 Happy Path

Happy Path 通常指最顺利的一条主路径；正向测试范围更广，可以包含合法但不常见的条件。

## 常见错误

- 只写一条最简单成功用例。
- 只断言状态码 200，不检查内容和持久化状态。
- 用正向测试掩盖缺少权限和异常用例。
