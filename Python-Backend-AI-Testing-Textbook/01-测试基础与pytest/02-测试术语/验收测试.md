# 验收测试

## 定义

验收测试从业务或用户角度确认系统是否满足已约定的验收条件。它回答“这个功能是否可以被业务接受”，而不关心内部用了哪个函数。

## 示例需求

“已登录用户上传 PDF 后，系统在两分钟内完成解析，并能回答文档中的问题且展示页码引用。”

验收条件可以写成：

```text
Given 用户已登录且拥有知识库权限
When 用户上传一份有效 PDF
Then 两分钟内文档状态变为 ready
And 用户提问时回答包含来源页码
```

这些条件可以人工执行，也可以自动化。

## 与 E2E 的关系

验收测试按业务目标分类；E2E 按技术范围分类。一条验收测试可能通过 API 完成，也可能是浏览器 E2E。两者有交集但不等同。

## 谁参与

产品、业务、开发、测试和安全人员应共同澄清。AI 功能还可能需要领域专家定义正确性、拒答和安全标准。

## 好的验收条件

可观察、可验证、没有模糊词。把“响应要快”改成“P95 在指定负载下小于 3 秒”；把“回答准确”改成基于评测集和评分规则的门槛。

## 常见错误

- 验收条件写成内部实现细节。
- 使用“友好、智能、足够快”等无法判定的词。
- 只写成功路径，不写权限、错误和无答案。
- 功能开发完成后才讨论验收标准。

## 练习与面试题

练习：把“聊天机器人好用”改写成 5 条可测试的验收条件。

面试：验收测试与系统测试、E2E 的区别是什么？
