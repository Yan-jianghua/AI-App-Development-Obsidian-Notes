# 测试用例

## 定义

测试用例是一组可重复执行的条件、操作和预期结果，用来验证一个具体行为。好用例回答：在什么前提下，输入什么，执行什么，应该看到什么。

## 基本组成

- 名称：条件和预期结果。
- 前置条件：已有用户、余额、权限等。
- 输入：函数参数、HTTP 请求或事件。
- 操作：执行被测行为。
- 预期结果：返回值、异常、状态和副作用。
- 清理：恢复环境，避免影响其他用例。

## 示例

需求：“VIP 用户订单满 100 元打八折。”

| 项目 | 内容 |
|---|---|
| 名称 | VIP 订单恰好 100 元时打八折 |
| 前置 | 用户等级为 VIP |
| 输入 | 订单金额 100 |
| 操作 | 计算实付金额 |
| 预期 | 返回 80，原订单金额不被修改 |

自动化代码：

```python
def test_vip_order_at_threshold_gets_discount():
    result = calculate_total(user_level="vip", total=100)
    assert result == 80
```

## 用例粒度

一个用例最好验证一个主要行为。可以有多个相关断言，例如同时检查返回值和必要副作用，但不要把登录、下单、退款十个行为塞进同一个单元测试。

## 命名方式

推荐“条件 + 结果”：`test_expired_token_is_rejected`。避免 `test_1`、`test_user` 这类看不出目的的名称。

## 常见错误

- 没有明确预期，只看是否报错。
- 测试数据很多但没有说明为什么选择。
- 用例依赖前一个用例先运行。
- 失败后不清理数据库或文件。
