# 端到端测试

## 定义

端到端测试（End-to-End，E2E）从用户入口开始，穿过前端、后端、数据库和必要依赖，验证完整业务流程。

## 示例

电商流程：打开页面→登录→搜索商品→加入购物车→提交订单→看到成功页面。自动化工具会像用户一样操作界面，再验证最终状态。

```python
def test_user_can_login(page):
    page.goto("http://test-app/login")
    page.get_by_label("邮箱").fill("alice@example.com")
    page.get_by_label("密码").fill("secret")
    page.get_by_role("button", name="登录").click()
    assert page.get_by_text("欢迎回来").is_visible()
```

代码只是概念示例，后续 Playwright 专篇会详细讲解。

## 价值

它能发现单个组件测试看不到的装配问题：错误 API 地址、Cookie 配置、浏览器 CORS、页面与后端字段不一致。

## 局限

E2E 运行慢、环境依赖多、失败定位困难。应选择少量最重要用户旅程，而不是用 E2E 穷举所有边界。

## 稳定性原则

使用独立测试数据、稳定选择器、等待可观察状态而非固定 sleep、失败时保存截图和 Trace。外部支付使用沙箱。

## 常见错误

- 依赖 CSS 层级定位，页面微调就失败。
- 共用同一账号，测试并行互相影响。
- 每个输入组合都写浏览器测试。
- 失败只得到“元素未找到”，没有日志或请求 ID。

## 练习与面试题

练习：选择一个 AI 问答产品的三条最值得做 E2E 的用户旅程。

面试：为什么 E2E 测试数量通常少于单元测试？
