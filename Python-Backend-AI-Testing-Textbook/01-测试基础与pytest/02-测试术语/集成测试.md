# 集成测试

## 定义

集成测试验证两个或多个真实组件能否正确协作，例如业务代码与 PostgreSQL、FastAPI 路由与依赖注入、生产者与消息队列。

## 为什么需要

单元测试中的 Fake 数据库可能接受任何查询，但真实 PostgreSQL 会受到 SQL 方言、约束、事务和时区影响。组件各自正确，并不保证连接起来正确。

## 示例

假设用户仓库负责保存和查找邮箱：

```python
def test_repository_saves_and_reads_user(db_session):
    repository = UserRepository(db_session)
    created = repository.create(email="alice@example.com")

    loaded = repository.get_by_email("alice@example.com")

    assert loaded.id == created.id
    assert loaded.email == "alice@example.com"
```

这里应连接测试 PostgreSQL，而不是只返回预设值。测试结束通过事务回滚或清理数据。

## 集成边界

一次集成测试不必连接全世界。可以只验证应用+数据库，也可以验证应用+Redis。边界越大，越接近真实环境，但速度和排障成本越高。

## 常见策略

- Docker/Testcontainers 启动临时服务。
- 使用供应商沙箱而非生产服务。
- 每个测试事务回滚。
- 为并行 worker 分配独立数据库或 Schema。

## 常见错误

- 名叫集成测试，实际上数据库也被 Mock。
- 直接使用开发或生产数据库。
- 依赖测试执行顺序和残留数据。
- 把外部网络波动误判为业务 Bug，却没有隔离和诊断信息。

## 练习与面试题

练习：列出“创建用户”功能中至少三个值得做真实集成测试的边界。

面试：为什么只使用 SQLite 测试生产 PostgreSQL 可能漏掉问题？
