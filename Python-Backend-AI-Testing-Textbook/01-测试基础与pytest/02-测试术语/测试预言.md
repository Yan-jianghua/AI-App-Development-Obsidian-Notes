# 测试预言

## 白话解释

测试预言（Test Oracle）是判断“实际结果到底对不对”的依据。执行代码很容易，难的是知道正确答案是什么。

## 常见预言来源

- 明确需求：税率规则、权限矩阵。
- 参考实现：用慢但简单的算法验证优化算法。
- 数学性质：排序后元素不变且有序。
- 数据库约束：用户名必须唯一。
- 标准协议：HTTP 状态码和 JSON Schema。
- 人工专家：法律、医疗或主观质量。
- 已批准 Golden 数据：解析器或 AI 评测标准答案。

## 简单例子

```python
def test_sort_result_is_ordered_and_preserves_items():
    original = [3, 1, 2, 1]
    result = custom_sort(original)
    assert result == [1, 1, 2, 3]
```

这里 `[1, 1, 2, 3]` 是具体预言。也可以用性质：结果有序且元素计数与原始列表相同。

## AI 为什么更难

LLM 可能有多个正确表达，无法总用字符串相等。测试预言可能是必须包含的事实、禁止内容、Schema、引用证据、评分 Rubric 或人工判断。预言本身也可能出错，因此要版本化和复核。

## 预言问题

- 需求含糊，不知道哪种结果才对。
- 用当前实现输出作为“正确答案”，把 Bug 固化进快照。
- 人工评审者标准不一致。
- 外部世界会变化，例如价格和法规。

## 最佳实践

优先使用客观、可解释、稳定的预言；主观任务使用清晰 Rubric 和多人校准；记录预言来源和版本。
