# 负向测试

## 定义

负向测试使用非法输入、禁止状态或失败依赖，确认系统能安全、明确地拒绝或恢复，而不是崩溃、泄漏信息或留下半完成数据。

## 示例

```python
import pytest

def test_login_rejects_wrong_password():
    with pytest.raises(AuthenticationError):
        login(email="alice@example.com", password="wrong")
```

API 层可能不抛异常，而返回 401 和稳定错误结构。测试应匹配所在层的对外契约。

## 常见负向维度

- 缺失、错误类型、超长、空白和恶意输入。
- 资源不存在、已删除、过期或状态不允许。
- 未认证、无权限、跨租户访问。
- 数据库、网络、模型、队列超时或返回异常。
- 重复请求、并发冲突和部分失败。

## 负向不等于随便输入垃圾

高质量负向用例来源于验证规则、状态机、协议、安全威胁和历史事故。每条用例要知道预期的拒绝方式。

## 检查内容

除了错误，还要验证：没有写入数据、没有发送外部通知、事务回滚、错误不泄漏内部信息、日志可诊断。

## 常见错误

- 只断言“发生任意异常”。
- 负向请求失败了，但数据库已经部分写入。
- 错误消息泄漏用户是否存在、SQL 或密钥。

## 练习与面试题

练习：为退款接口列出输入、权限、状态、并发和依赖五类负向场景。

面试：负向测试除了检查报错，还必须检查什么？
