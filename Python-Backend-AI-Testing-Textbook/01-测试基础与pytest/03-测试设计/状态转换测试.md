# 状态转换测试

## 定义

状态转换测试验证对象在事件发生后能否从当前状态进入正确的新状态，并拒绝非法转换。

## 订单例子

状态：`draft → paid → shipped → completed`，另有 `cancelled`。

```python
def test_paid_order_can_be_shipped():
    order = Order(status="paid")
    order.ship()
    assert order.status == "shipped"

def test_completed_order_cannot_be_cancelled():
    order = Order(status="completed")
    with pytest.raises(InvalidTransition):
        order.cancel()
```

第二条与第一条同样重要，因为非法转换可能造成退款、库存或审计错误。

## 设计步骤

1. 列出所有状态。
2. 列出触发事件。
3. 画出允许转换。
4. 为每条允许转换写测试。
5. 为高风险非法转换写拒绝测试。
6. 检查转换副作用和幂等性。

## 序列问题

有些 Bug 只有经过一串操作才出现，例如“失败→重试→取消→再次完成”。可使用状态机或属性测试自动生成序列。

## 常见错误

- 只测试最终状态，不检查事件、时间和审计记录。
- 允许重复事件产生重复副作用。
- 并发状态更新时旧版本覆盖新状态。

## 练习与面试题

练习：为后台 AI 任务的 queued、running、succeeded、failed、cancelled 画状态图。

面试：状态转换测试为什么必须包含非法路径？
