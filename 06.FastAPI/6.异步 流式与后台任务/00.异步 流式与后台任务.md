# 异步、流式响应与后台任务

## `async` 的适用范围

异步适合等待网络、数据库和文件等 I/O；它不会让 CPU 密集计算自动变快。`async def` 中调用阻塞函数会卡住事件循环，影响同一进程的其他请求。

```python
import asyncio
import httpx

async def fetch_two() -> list[dict]:
    async with httpx.AsyncClient(timeout=10) as client:
        a, b = await asyncio.gather(
            client.get("https://api.example.com/a"),
            client.get("https://api.example.com/b"),
        )
    return [a.json(), b.json()]
```

并发不是无限并行：要限制并发数、连接池和外部配额。一个子任务失败时明确其他任务是取消、继续还是收集错误。

## `def` 与 `async def`

- 端点主要调用支持 `await` 的库：使用 `async def`。
- 使用阻塞式第三方库：普通 `def` 可由框架在线程池处理，或显式迁移到异步客户端。
- CPU 密集的 OCR、视频、模型推理：交给进程、任务队列或独立服务。

## 流式响应与 SSE

模型逐 token 输出可用 `StreamingResponse` 或 SSE。必须处理客户端断开、生成器取消、上游连接关闭、心跳、缓冲与错误事件。代理也可能缓冲响应，需要相应配置。

```python
from fastapi.responses import StreamingResponse

async def events():
    for word in ["hello", " ", "world"]:
        yield f"data: {word}\n\n"
        await asyncio.sleep(0.05)

@app.get("/stream")
async def stream():
    return StreamingResponse(events(), media_type="text/event-stream")
```

## 后台任务与队列

响应后执行的轻量、短任务可用应用内后台任务；需要重试、持久化、跨进程、长时间或高资源的任务应使用队列/工作进程。任务至少包含唯一 ID、状态、重试策略和幂等设计。

```text
POST /jobs → 202 + job_id
worker 消费任务 → 更新 queued/running/succeeded/failed
GET /jobs/{id} → 查询状态或结果
```

## 常见错误

- 以为加 `async` 就能提高 CPU 推理速度。
- 每个请求创建新的 HTTP 客户端，失去连接复用。
- 无上限 `gather` 导致文件描述符、内存或外部配额耗尽。
- 响应已返回但应用进程重启，使内存后台任务丢失。
- 流式请求结束后未记录完整耗时、Token 和最终状态。

## 练习

设计“异步生成报告”接口：提交返回 202，工作进程生成，客户端轮询或 SSE 获取进度；说明去重、取消、超时和失败重试。
