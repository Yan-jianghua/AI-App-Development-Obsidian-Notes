# Pydantic 与数据校验

## 请求模型和响应模型要分开

创建、更新、数据库内部对象和公开响应的字段通常不同。分开模型可以防止客户端设置 `id`、`role` 等服务端字段，也能避免响应泄露 `password_hash`。

```python
from datetime import datetime
from pydantic import BaseModel, ConfigDict, Field

class NoteCreate(BaseModel):
    title: str = Field(min_length=1, max_length=100)
    content: str = Field(max_length=20_000)

class NoteUpdate(BaseModel):
    title: str | None = Field(default=None, min_length=1, max_length=100)
    content: str | None = Field(default=None, max_length=20_000)

class NoteRead(BaseModel):
    model_config = ConfigDict(from_attributes=True)
    id: int
    title: str
    created_at: datetime
```

`Optional`/`T | None` 表示值可为 `None`，不一定表示字段可省略；是否有默认值决定是否必填。PATCH 更新时还要区分“未提供字段”和“明确提供 null”，可用 `model_dump(exclude_unset=True)`。

## 校验层次

- 字段校验：长度、范围、格式。
- 模型校验：起止时间、字段组合等跨字段规则。
- 业务校验：用户名是否存在、余额是否足够，应在 service 层访问依赖。
- 数据库约束：唯一键、外键、非空，是并发条件下最后防线。

不要把需要数据库 I/O 的规则塞进纯数据模型，也不要只靠前端校验。

## 序列化与严格边界

```python
payload = note.model_dump(exclude_none=True)
json_text = note.model_dump_json()
```

对外响应声明 `response_model`，只输出契约字段。对金额、枚举、URL、邮箱、日期等选择恰当类型；对未知字段是否拒绝要按接口演进策略决定。模型升级时要考虑旧客户端。

## 设置管理

配置应在启动时解析并校验，开发环境可从 `.env` 加载，但 `.env` 不提交。生产密钥来自密钥管理系统或受保护的环境注入。日志只能打印“配置项是否存在”和非敏感元数据。

## 常见错误

- 认为类型提示会自动检查普通 Python 函数；类型提示本身不执行运行时校验。
- 把数据库模型当公开 API 模型。
- 使用可变默认值而不了解其复制行为。
- 对字符串只检查类型，不限制空白、长度和允许字符。
- 对客户端返回框架内部的完整校验细节，造成实现泄露或前端强耦合。

## 练习

为注册接口设计模型：用户名、邮箱、密码、确认密码与生日；明确哪些是字段校验、跨字段校验和业务校验，并设计安全的错误响应。
