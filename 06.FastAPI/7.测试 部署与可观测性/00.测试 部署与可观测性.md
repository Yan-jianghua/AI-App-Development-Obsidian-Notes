# 测试、部署与可观测性

## 测试分层

- 业务单元测试：直接调用 Service，替换数据库和外部模型。
- API 测试：通过 ASGI 测试客户端验证路由、校验、状态码与依赖。
- 集成测试：使用真实 PostgreSQL/Redis 等依赖验证事务和协议。
- 端到端测试：覆盖少量关键用户流程。

```python
from fastapi.testclient import TestClient
from app.main import app

client = TestClient(app)

def test_health() -> None:
    response = client.get("/health")
    assert response.status_code == 200
    assert response.json() == {"ok": True}
```

若应用全异步，使用异步客户端与 ASGI transport，并确保生命周期钩子被执行。通过 `app.dependency_overrides` 替换认证或资源依赖，测试后清理覆盖。

## 部署结构

```text
Internet → Load Balancer/Nginx → ASGI workers → FastAPI
                                      ↓
                             PostgreSQL/Redis/外部API
```

容器镜像固定依赖版本，使用非 root 用户，配置健康检查和只读文件系统（按需挂载可写目录）。多 worker 能利用多核，但每个 worker 都有自己的内存、连接池和模型副本，不能盲目增加。

## 健康检查

- Liveness：进程是否活着，失败会被重启；不应依赖所有外部服务。
- Readiness：是否能接收流量，可检查关键初始化和依赖。
- Startup：慢启动应用是否完成加载，避免启动期被误杀。

## 可观测性

日志回答“发生了什么”，指标回答“多频繁、多慢”，追踪回答“一次请求经过哪些组件”。至少监控请求量、错误率、延迟分位数、并发、队列长度、连接池、外部调用和模型成本。

结构化日志携带 request/trace ID、路由模板、状态码和耗时，避免把高基数原始 URL 当指标标签。

## 发布与停机

滚动发布需要新旧版本短期兼容同一数据库。收到终止信号后停止接收新流量、等待在途请求、关闭连接池和消费者，并在平台的宽限期内结束。数据库迁移采用扩展—迁移—收缩步骤。

## 上线清单

- 配置和密钥来自环境，启动时校验。
- 超时、重试、限流、请求大小和并发上限明确。
- 文档/调试端点按环境控制。
- HTTPS、安全 Header、CORS 与可信代理配置正确。
- 测试、迁移、回滚和备份恢复方案已演练。

## 综合练习

把笔记 API 容器化，接 PostgreSQL；为创建、并发冲突、越权、数据库不可用和优雅停机各写一个验证场景。
