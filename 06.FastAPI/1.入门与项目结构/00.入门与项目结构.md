# FastAPI 入门与项目结构

## 请求如何到达函数

ASGI 服务器接收网络请求并调用 FastAPI；FastAPI 匹配路由、解析参数、执行依赖、调用端点函数，再序列化响应。框架自动生成的 OpenAPI 文档来自路径、类型和模型，不能替代真实业务说明。

## 路径与参数

```python
from typing import Annotated
from fastapi import FastAPI, Query

app = FastAPI()

@app.get("/items/{item_id}")
async def get_item(
    item_id: int,
    q: Annotated[str | None, Query(max_length=50)] = None,
) -> dict:
    return {"id": item_id, "q": q}
```

路径参数来自 URL 路径，查询参数来自 `?q=`，请求体通常由 Pydantic 模型描述。固定路径如 `/items/latest` 应避免被动态路径 `/items/{item_id}` 错误吞掉。

## 推荐结构

```text
app/
  main.py             # 创建应用、挂载路由、生命周期
  api/routes/         # HTTP边界，保持薄
  schemas/            # 请求与响应模型
  services/           # 用例/业务逻辑
  repositories/       # 数据访问
  core/config.py      # 配置与安全基础设施
  db/                 # 会话、模型、迁移
tests/
```

路由函数负责协议转换：读取请求、调用 service、映射错误与响应。复杂规则放在业务层，数据库查询放在 repository；这样单元测试不必启动 HTTP 或真实数据库。

## 响应与异常

```python
from fastapi import HTTPException, status

if item is None:
    raise HTTPException(
        status_code=status.HTTP_404_NOT_FOUND,
        detail="item not found",
    )
```

生产项目应定义统一错误结构和全局异常处理器：预期业务错误映射为稳定的 4xx；未知错误记录 request ID 后返回通用 500。不要把异常字符串、SQL 或堆栈直接回传。

## 生命周期

数据库池、HTTP 客户端和模型客户端应在应用启动时创建，在关闭时释放，避免每个请求重新建立昂贵连接。启动失败应让服务保持“不就绪”，而不是带着半初始化状态接收流量。

## 常见错误

- 把所有代码放进 `main.py`。
- 直接返回 ORM 对象且未限定响应字段，意外泄露敏感列。
- 用全局可变字典保存生产数据，多进程间不共享且重启丢失。
- 在开发服务器正常就认为生产部署完成。
