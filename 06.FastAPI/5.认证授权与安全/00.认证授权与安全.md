# 认证、授权与 API 安全

## 密码与令牌

密码只保存现代密码哈希，不可逆加密或明文。登录成功后可签发短期访问令牌；刷新令牌需要轮换、撤销和泄露处理。JWT 的载荷通常可被读取，不能放秘密；服务器必须校验算法、签名、过期时间、签发者和受众。

```python
async def get_current_user(token: str = Depends(oauth2_scheme)) -> User:
    claims = verify_token(token)
    user = await users.get(claims["sub"])
    if user is None or not user.is_active:
        raise credentials_error
    return user
```

示例省略了具体库配置，真实实现不要自己发明密码学算法。

## 授权

角色只是授权输入之一。每次访问资源都验证对象归属、租户、角色/权限和资源状态，防止越权读取与修改。管理操作记录审计事件。

```text
认证：token 属于用户 7
授权：用户 7 是否能读取文档 42？
```

## 输入与输出安全

- 文件上传校验大小、媒体类型和实际内容，随机化存储名，放在 Web 根目录之外。
- 不把用户输入拼入 SQL、Shell、模板或 URL；使用参数化查询和白名单。
- 防 SSRF：限制协议、域名/IP 范围、重定向和响应大小。
- 响应模型排除哈希、内部 ID、调试字段和其他租户数据。
- CORS 只允许可信来源；它不能代替认证与授权。

## 限流与滥用控制

按用户、API Key、IP 或租户设定速率与并发配额。对登录、验证码、模型推理和文件处理设置更严格限制。限制失败要可观测，并避免仅靠单进程内存计数器处理多实例部署。

## 安全响应

认证失败通常用 `401` 并提供合适认证提示；已认证但无权用 `403`。有时为避免泄露资源存在性可统一返回 `404`。安全日志写用户/租户 ID、动作、结果、请求 ID，不记录密码和完整 Token。
