## 推荐实施方式

1. 每个项目先完成一条真实、可测试的纵向业务闭环，再扩展功能。
2. 前一个项目的代码可以复用，但要抽取稳定边界：模型适配、身份与租户、评测数据、追踪、预算和审批。
3. 每到下一项目，新增至少一个前一项目没有证明的能力，而非只更换业务场景。
4. 在独立仓库或清晰隔离的服务中开发，保留需求、架构决策、失败案例和指标变化。
5. 使用 [[00.六项目共同交付标准]] 检查是否达到可展示水平。
6. 每个项目从 `001` 起阅读独立知识点，并用 `009.项目验收测试` 交叉核对 [[13.测试/测试|测试章节]]。
7. 用 [[00.AI应用开发知识覆盖矩阵]] 检查从 Python 后端到 AI 应用交付的知识闭环。

## 能力递进

```text
模型调用与评测
  → 带权限的企业知识检索
  → 可恢复、可核验的 Agent
  → 完整业务平台
  → 可供多个应用使用的 AI 控制平面
  → 跨参与方的交易证据与争议协同产品
```

**重要原则：**规划书中的 P0、P1 和强化阶段要分开。未完成的目标应标为“规划”或“待验证”；作品集只陈述实际运行、实际测试和实际测得的指标。
