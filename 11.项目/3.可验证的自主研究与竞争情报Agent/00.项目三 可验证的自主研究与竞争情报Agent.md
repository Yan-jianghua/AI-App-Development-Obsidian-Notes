## 项目定位

把复杂研究问题拆成可审计计划，由受限 Agent 搜索、阅读、计算、交叉核验，再生成带证据的报告。原规划书计划核心约 17 周、作品集 V1 约 180—260 小时。核心难点是可恢复编排与证据核验，而非增加 Agent 数量。

## 第一条可运行闭环

用户提交研究问题 → 系统生成可编辑计划 → 并行执行两个研究子任务 → 保存 checkpoint → 对每条结论关联可访问来源 → 人工确认后发布报告。

## 必做模块

| 模块 | 要实现的行为 | 关键边界 |
|---|---|---|
| 研究领域模型 | 任务、证据、结论、冲突、审批、报告版本 | 事实、推断和用户陈述分开记录 |
| 工具执行器 | 搜索、网页读取、计算、文件解析 | 网络、代码和外部动作在沙箱/策略内运行 |
| 图编排 | DAG、并行、重试、暂停、恢复、取消 | 重放不会重复外部副作用 |
| 证据核验 | 去重、来源质量、时效、冲突、计算复核 | 结论不能只凭模型自述成立 |
| 报告协作 | 编辑、引用、版本、导出、审批 | 发布内容可追溯到具体证据版本 |
| 评测与红队 | 任务集、轨迹指标、注入与故障测试 | 不只评价最终文案，也检查路径和工具动作 |

## 建议实施顺序

1. 建立任务、证据、结论和审批数据模型，定义来源可信度与时效规则。
2. 实现只读搜索/读取/计算工具，设置白名单、超时和预算。
3. 用显式图实现两任务并行、检查点、失败重试与人工中断。
4. 增加结论到证据的关系和冲突报告，再做报告编辑与导出。
5. 运行正常、注入、断网、重启、重复回调等路径测试。

## 可展示的验收证据

- 中途重启后从 checkpoint 恢复，不重复已完成副作用。
- 生成一份含来源、日期、冲突说明和可复核计算的研究报告。
- 展示一条“证据不足 → 不生成确定结论”的路径。
- 对提示注入、坏网页、工具超时和来源冲突给出测试轨迹。

## 常见缩水风险

多 Agent 自由聊天可能看起来热闹，但难以证明正确性。把“证据质量、可恢复状态机、人工审批”做实，比堆角色和工具更有说服力。

## 为下一项目留下什么

保留受控工具、审批、幂等、检查点和证据图；项目四将把这些能力接入订单、客服和经营分析等真实业务域。
