# SSE流式协议

## 是什么与为什么

SSE 通过持久 HTTP 响应逐条发送事件，适合单向生成内容。应用必须定义事件类型，而不是把供应商 token 原样透传。

## 实现要点

建议事件含 `request_id`、`sequence`、`type`、`payload`；类型可有 `start`、`delta`、`tool_call`、`usage`、`finish`、`error`。服务端持久化最终消息与终止状态，客户端按序号去重并在断线后读取会话状态。明确取消请求是否停止上游计费。

## 边界、测试与验收

不要承诺任意断点都能重放未持久化 token。代理缓冲、反向代理超时、浏览器断线都会改变行为。测试慢客户端、连接中断、重复事件、错误中途发生和用户取消，最终消息不可重复。

## 动手练习

用假模型依次发 start、delta、usage、finish，再分别在第二个 delta 后断网和取消。刷新页面后最终任务状态明确，内容与计费记录不重复。

把输入、预期、实际结果、版本和失败样本写入测试记录；只有可重复运行才算掌握。
