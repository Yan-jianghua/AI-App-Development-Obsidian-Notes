## 项目定位

为企业构建可按权限查阅的知识问答系统。它要解决普通 RAG Demo 缺少租户隔离、文档版本、引用定位和质量评测的问题。原规划书计划核心约 17 周，作品集 V1 约 180—240 小时。

## 第一条可运行闭环

管理员上传一份带访问权限的文档 → 异步解析、切分和建索引 → 授权用户提问 → 系统返回附页码/段落/版本的答案 → 无权用户完全检索不到该文档。

## 必做模块

| 模块 | 要实现的行为 | 关键边界 |
|---|---|---|
| 租户与 ACL | 用户、组织、文档权限继承 | 检索前或检索中强制过滤，不依赖模型遵守权限 |
| 摄取流水线 | 连接器、PDF/OCR、队列、幂等重试 | 原件与派生文本可追溯 |
| 索引与检索 | 关键词、向量、混合检索、重排 | 版本与权限过滤进入查询路径 |
| 回答与引用 | 证据拼装、拒答、冲突识别、来源预览 | 引用必须指向本次授权证据 |
| 治理后台 | 更新、失效、删除、审计与索引状态 | 旧版本不能继续回答 |
| 评测 | 黄金集、Recall@K、引用正确率、无答案集 | 变更前后有可复现对比 |

## 建议实施顺序

1. 先建立租户、组织、ACL、文档版本和威胁模型。
2. 以 Markdown 和文本 PDF 做摄取闭环，再逐步加入 OCR 与连接器。
3. 先用关键词检索建立基线，再加向量、融合与重排。
4. 增加回答和引用校验，并针对权限、过期版本和冲突文本构造测试。
5. 完成删除传播、评测门禁、SSO/限流、备份和部署。

## 可展示的验收证据

- 同一问题在不同租户/角色下返回不同的授权证据；越权访问全部被拒绝。
- 修改文档后，索引更新且引用指向正确版本；删除后旧证据不再出现。
- 展示检索 Recall@K、答案忠实度、引用正确率及失败分类。
- 用一份表格 PDF 和一份扫描件展示解析质量检查与错误处理。

## 常见缩水风险

“上传 PDF → 向量搜索 → 模型回答”只是入门演示。该项目真正的含金量在 ACL 安全检索、增量索引、版本治理和可验证引用。

## 为下一项目留下什么

保留文档解析、检索、证据 ID、权限过滤和引用校验；项目三将在此基础上增加多步骤研究、工具沙箱与可恢复执行。
