# 业务事件与数据管道

## 是什么与为什么

商品、订单、客服和物流来自多个外部平台，事件管道决定数据最终是否一致、可重放和可追溯。

## 实现要点

为外部 webhook 验签并保存原始事件、平台事件 ID 与接收时间；使用去重键与重试队列。状态更新依据事件版本或业务时间防止旧事件覆盖新状态。定期与平台 API 对账，发现缺失后补拉。

## 边界、测试与验收

测试乱序、重复、延迟、签名错误、死信和平台限流。不要假设 exactly-once；以幂等消费与补偿实现业务层一致性。

## 动手练习

逆序发送支付、发货、签收 webhook，再补发旧事件；最终状态应保持最新且对账能发现故意遗漏的事件。

把输入、预期、实际结果、版本和失败样本写入测试记录；只有可重复运行才算掌握。
