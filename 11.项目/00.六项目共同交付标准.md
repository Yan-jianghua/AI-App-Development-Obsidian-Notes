# 六项目共同交付标准

所有项目都要区分“计划做”“正在做”“已验证完成”。项目编号不代表实际成果，只有达到可重复运行和可审查的证据后，才适合写进作品集。

## 最小交付包

| 交付物 | 必须包含 |
|---|---|
| README | 用户问题、核心功能、架构、运行/测试/停止步骤、已知限制 |
| 架构记录 | 组件边界、数据流、关键取舍与至少一个被放弃的方案 |
| 数据和接口 | Schema、迁移、API/事件契约、示例数据和错误码 |
| 自动化测试 | 单元、集成、权限、异常和关键端到端路径 |
| AI 评测 | 固定数据集、版本、指标、失败分类和回归比较 |
| 安全与隐私 | 权限、密钥、审计、数据隔离、保留/删除和对抗测试 |
| 运维 | 容器启动、CI、健康检查、日志、指标、追踪、备份与回滚说明 |
| 展示材料 | 可运行 Demo、测试报告、真实指标、问题与修复案例 |

## 每个里程碑的退出条件

完成一条纵向业务路径，自动化检查通过，有可运行演示，失败场景被记录，README 与实际代码一致。涉及外部副作用的动作必须有审批、授权、幂等和审计。未通过门禁的功能留在待办，不用“功能基本完成”代替验收。

## AI 项目必须测什么

质量：任务成功率、事实忠实度、引用/结构化输出正确率、应拒答时的表现。工程：P95 延迟、错误率、重试、断线恢复、成本与预算。安全：越权、提示注入、工具误调用、敏感信息泄露。每项指标都记录测试数据来源、样本量和版本。

## 作品集讲述顺序

用 3—5 分钟说清：真实问题 → 第一条业务闭环 → 架构与关键取舍 → 可运行演示 → 测试/评测证据 → 一次失败的定位与改进 → 当前限制。避免只展示规划书或静态截图。

## 复用原则

复用通过测试的基础能力，不把六个项目硬塞进同一庞大仓库。每次复用都要重新检查租户边界、数据模型、错误语义、部署环境和安全权限，避免把前一个项目的假设带到新场景。
