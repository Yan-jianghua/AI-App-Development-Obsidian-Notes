## 项目定位

为消费者与商家建立中立的交易证据和售后协同空间：购买时保存承诺快照，出现争议后整理订单、物流、沟通与政策，双方核对事实，Agent 提出可审查建议，人在确认后才对外发送或执行动作。规划书把它定位为约 800 小时的工程级 MVP，首发中英文实物电商五类案件。

项目含金量来自双边业务、证据可信度、浏览器扩展、跨平台连接、长时工作流、隐私安全与真实用户验证的组合。它的计划规模最大，同时也有最高的市场和接入不确定性；先过需求验证门槛，再投入完整开发。

## 第一条可运行闭环

消费者主动保存测试商品页承诺 → 导入订单、物流和图片 → 创建案件并生成证据时间线 → Agent 提示缺口和候选方案 → 用户批准邀请商家 → 双方确认事实、提出与接受方案 → 导出带来源、版本和审计信息的中英文案件包。

## 首发边界

- 案件类型：未收到货、破损、货不对板、退货退款、保修。
- 数据来源：用户主动捕获网页、邮件收据、测试订单、物流事件、图片和聊天导出。
- 用户端：消费者 Web/PWA、浏览器扩展；商家端：受邀案件门户与轻量 API。
- Agent 负责抽取、整理、缺口提示、政策匹配和草稿；发送、接受、退款申请及公开分享必须人工确认。
- 不做自动法律裁决、强制退款或未经授权访问平台数据；快照的哈希与时间记录不应被表述为天然具有司法证据效力。

## 必做模块

| 模块 | 要实现的行为 | 关键边界 |
|---|---|---|
| 交易与证据 | 承诺快照、原件存储、哈希、来源、版本 | 原件、用户陈述和 AI 推断清楚区分 |
| 案件状态机 | 草稿、待协商、审批、解决与导出 | 状态转移、期限和金额由确定性代码控制 |
| 双边协作 | 邀请、最小共享、事实确认、方案讨论 | 参与方只能看到授权材料 |
| Agent 与政策 | 分类、字段抽取、缺口、条款匹配、双语草稿 | 每个关键结论带证据或标为不确定 |
| 连接器 | 浏览器扩展、邮件、Shopify 沙盒、物流模拟 | Webhook 幂等、凭据隔离、平台条款遵守 |
| 案件包 | PDF/JSON、时间线、附件索引、审计 | 导出版本可验证，记录审批与来源 |

## 分阶段实施

1. **M0 需求验证：**访谈消费者和商家，检查真实痛点、使用意愿和平台接入边界；形成 Go/No Go 结论。
2. **M1 工程骨架：**身份、租户、迁移、CI、监控与数据模型。
3. **M2 单边闭环：**消费者导入订单、创建案件、整理时间线并导出案件包。
4. **M3 双边协作：**商家受邀、事实核对、方案与审批、通知。
5. **M4 Agent 与连接器：**政策解析、候选补救、邮件与 Shopify 沙盒。
6. **M5/M6 安全和公测：**红队、性能、恢复、无障碍、部署、反馈与复盘。

## 可展示的验收证据

- 原始证据和派生事实有来源、时间、哈希、权限与处理记录，可从结论回查原件。
- 用户与商家能看到同一案件中哪些事实已确认、哪些仍有分歧。
- Agent 不会在缺少批准时发送消息、接受方案或提交退款；重复回调不会重复执行。
- 五类案件各有主路径和异常路径；关键字段、引用、政策版本与双语金额/期限有评测结果。
- 至少一条从网页快照到案件包导出的公开可演示路径，以及测试用户反馈。

## 最大风险

平台接口限制、双边冷启动、证据真实性争议、隐私泄露和范围膨胀，都可能让技术演示与真实产品价值脱节。规划书要求先做 M0 验证，并保留单边消费者证据整理的独立价值；无法满足验证条件时应收缩或转向，而不把 800 小时全部投入未经验证的假设。

## 与项目五的区别

项目五证明你能造 AI 基础设施；TradeProof 证明你能把基础设施、业务流程、跨方协作和产品验证合在一起。若只评价 AI 平台岗位的技术针对性，项目五可更靠前；按综合产品与工程跨度，TradeProof 作为最后的旗舰项目。
