# Liskov Substitution Principle

## 什么是里氏替换原则

Liskov Substitution Principle：

```text
LSP
```

中文：

> 里氏替换原则。

核心思想：

> 任何需要父类对象的地方，都应该可以安全地换成子类对象。

---

## 正确示例

```python
class Bird:

    def eat(self):
        print("吃东西")


class Sparrow(Bird):

    def eat(self):
        print("麻雀吃东西")
```

函数：

```python
def feed(bird: Bird):
    bird.eat()
```

既可以：

```python
feed(Bird())
```

也可以：

```python
feed(Sparrow())
```

都正常工作。

这符合里氏替换原则。

---

# 违反里氏替换原则

假设：

```python
class Bird:

    def fly(self):
        print("飞行")
```

然后：

```python
class Penguin(Bird):

    def fly(self):
        raise Exception("企鹅不会飞")
```

如果代码：

```python
def make_fly(bird: Bird):
    bird.fly()
```

正常传：

```python
Bird()
```

没问题。

换成：

```python
Penguin()
```

却直接失败。

说明：

> `Penguin` 并不能真正替代这里期待的 `Bird`。

这说明类设计可能有问题。

更合理的设计可能把：

```text
Bird
```

和：

```text
FlyingBird
```

分开。

---

# LSP 核心不是“子类能继承”

子类语法上能写：

```python
class Child(Base):
```

不代表设计就一定合理。

真正应该考虑：

> Child 能不能在所有合理场景下替代 Base，而不破坏原来的代码逻辑？
