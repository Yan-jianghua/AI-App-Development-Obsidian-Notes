# Python 虚拟环境![[022 63-66h pip_虚拟环境.docx]]与依赖管理

## `python -m venv .venv`

### 作用

创建一个 Python 虚拟环境。

### 命令

```
python -m venv .venv
```

含义：

```
python -m venv
= 使用 Python 自带的 venv 模块创建虚拟环境

.venv
= 虚拟环境文件夹名称
```

创建后项目里通常会出现：

```
project/
├── .venv/
└── main.py
```

### 为什么需要虚拟环境

不同项目可以使用不同版本的第三方库，互不影响。

例如：

```
项目 A → FastAPI 0.x
项目 B → FastAPI 另一个版本
```

### 一句话记忆

> `python -m venv .venv` = 给当前项目创建独立 Python 环境。

---

# `Activate.ps1`

## 作用

在 Windows PowerShell 中**激活虚拟环境**。

如果虚拟环境叫：

```
.venv
```

通常执行：

```
.\.venv\Scripts\Activate.ps1
```

激活后终端前面通常出现：

```
(.venv)
```

例如：

```
(.venv) PS C:\Users\xxx\project>
```

表示当前使用的是这个项目的虚拟环境。

### 一句话记忆

> `Activate.ps1` = Windows PowerShell 激活虚拟环境。

---

# `source`

## 作用

在 Linux / macOS 中常用来激活虚拟环境。

### 命令

```
source .venv/bin/activate
```

这是 Linux/macOS 常见写法。

Windows PowerShell 一般不用：

```
source
```

而是：

```
.\.venv\Scripts\Activate.ps1
```

### 一句话记忆

> `source` = Linux/macOS 常见的虚拟环境激活方式。

---

# `python -m pip`

## 作用

使用**当前 Python 解释器对应的 pip**。

推荐写：

```
python -m pip
```

而不只是：

```
pip
```

因为这样更容易保证 pip 对应的是当前 Python 环境。

---

# `python -m pip install`

## 作用

安装第三方库。

### 示例

```
python -m pip install requests
```

安装指定版本：

```
python -m pip install requests==2.32.5
```

### 一句话记忆

> `pip install` = 安装库。

---

# `python -m pip uninstall`

## 作用

卸载第三方库。

```
python -m pip uninstall requests
```

### 一句话记忆

> `pip uninstall` = 卸载库。

---

# `python -m pip list`

## 作用

查看当前环境中已经安装的第三方库。

```
python -m pip list
```

会显示类似：

```
Package    Version
---------- -------
requests   2.32.5
fastapi    ...
```

### 一句话记忆

> `pip list` = 查看已经安装了什么。

---

# `python -m pip show`

## 作用

查看某个库的详细信息。

### 示例

```
python -m pip show requests
```

可以看到：

```
版本
安装位置
依赖
简介
```

### 一句话记忆

> `pip show` = 查看某一个库的详细信息。

---

# `python -m pip check`

## 作用

检查当前环境中的依赖是否存在冲突或缺失。

### 命令

```
python -m pip check
```

如果没有问题，通常会提示类似：

```
No broken requirements found.
```

### 一句话记忆

> `pip check` = 检查依赖有没有坏掉。

---

# `python -m pip freeze`

## 作用

把当前环境中的库和版本输出成：

```
库名==版本
```

### 示例

```
python -m pip freeze
```

输出类似：

```
fastapi==...
requests==2.32.5
uvicorn==...
```

最常见用途：

```
python -m pip freeze > requirements.txt
```

把依赖保存到文件。

### 一句话记忆

> `pip freeze` = 导出当前环境的依赖版本。

---

# `requirements.txt`

## 作用

记录项目需要安装哪些 Python 第三方库。

例如：

```
fastapi==0.XXX
uvicorn==0.XXX
requests==2.32.5
```

别人拿到你的项目后，可以根据这个文件安装依赖。

### 生成

```
python -m pip freeze > requirements.txt
```

### 一句话记忆

> `requirements.txt` = 项目依赖清单。

---

# `pip install -r`

## 作用

根据依赖文件批量安装库。

### 示例

```
python -m pip install -r requirements.txt
```

这里：

```
-r
```

表示：

> 从文件中读取 requirements。

### 使用场景

你把项目上传到 GitHub：

```
代码
requirements.txt
```

别人下载后：

```
python -m venv .venv
```

激活虚拟环境，再：

```
python -m pip install -r requirements.txt
```

就能快速恢复项目环境。

### 一句话记忆

> `pip install -r requirements.txt` = 按依赖文件批量安装。

---

# `pyproject.toml`

## 作用

现代 Python 项目中非常重要的**项目配置文件**。

它可以记录：

- 项目信息
    
- Python 版本要求
    
- 项目依赖
    
- 构建配置
    
- 开发工具配置
    

### 简单示例

```
[project]
name = "my-project"
version = "0.1.0"

dependencies = [
    "requests",
    "fastapi"
]
```

相比：

```
requirements.txt
```

`pyproject.toml` 能管理的信息更多。

---

# `requirements.txt` 和 `pyproject.toml`

简单理解：

|文件|主要作用|
|---|---|
|`requirements.txt`|依赖安装清单|
|`pyproject.toml`|整个 Python 项目的标准配置文件|

你现在学习阶段：

> 先熟练掌握 `requirements.txt`，然后理解 `pyproject.toml`。

以后正式项目里会越来越常见：

```
pyproject.toml
```

# 一个完整项目流程

## 1. 创建项目

```
mkdir my_project
cd my_project
```

## 2. 创建虚拟环境

```
python -m venv .venv
```

## 3. Windows PowerShell 激活

```
.\.venv\Scripts\Activate.ps1
```

## 4. 安装依赖

```
python -m pip install requests
```

## 5. 查看依赖

```
python -m pip list
```

## 6. 导出依赖

```
python -m pip freeze > requirements.txt
```

以后项目目录可能是：

```
my_project/
├── .venv/
├── main.py
└── requirements.txt
```

# 换电脑或别人运行项目

不需要复制：

```
.venv
```

只需要：

```
代码
+
requirements.txt
```

然后重新创建：

```
python -m venv .venv
```

激活后：

```
python -m pip install -r requirements.txt
```

即可重新安装环境。
