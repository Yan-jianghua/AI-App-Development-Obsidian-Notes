# Agent 生产安全与评测

## 安全边界

模型、网页、检索片段和工具输出都不能直接决定权限。工具执行层验证身份、授权、参数、目标资源和预算；敏感工具采用最小权限、沙箱与审批。

## 可观测性

一次运行记录 trace ID、提示版本、模型、每个节点的开始/结束、工具参数摘要、延迟、Token、费用和最终状态。敏感内容脱敏，原始输入按保留政策管理。

## 评测分层

1. 工具单测：参数校验、权限和错误映射。
2. 节点测试：给定状态，验证输出状态。
3. 路径测试：分支、循环上限、审批、恢复与取消。
4. 任务评测：真实目标完成率、步骤数、成本和安全违规率。

成功率不能只靠模型自评，要检查外部状态，例如邮件是否真的发送、订单是否真的更新，并验证未授权动作没有发生。

## 上线策略

先只读工具，再影子运行，随后对低风险写操作开放小流量。设置全局 kill switch、单用户预算、监控与回滚。框架升级前运行固定回归集，因为默认 Agent 行为和消息格式可能变化。

## 常见失败

- 工具描述含糊，模型选错工具。
- 工具返回过长，挤掉重要上下文。
- 状态无限增长，延迟和费用上升。
- 循环没有终止条件。
- 只测“理想路径”，不测工具超时和恶意内容。

## 练习

给订单客服 Agent 建 15 条测试：正常查询、越权、重复取消、审批拒绝、工具超时、提示注入等；对每条写可观察的通过标准。
