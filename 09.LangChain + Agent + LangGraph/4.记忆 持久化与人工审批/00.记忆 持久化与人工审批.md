# 记忆、持久化与人工审批

## 三种不同的状态

- 本次运行的短期状态：当前问题、步骤和工具结果。
- 会话状态：同一用户多轮交互中的上下文。
- 长期记忆：经筛选、可删除的用户偏好或事实。

不要把所有对话原文都永久放进“记忆”。给每条数据定义来源、用户/租户归属、保留期限、可更正与删除方式。

## Checkpoint

检查点保存图运行状态，支持暂停和恢复。恢复时确认代码版本、状态 schema、用户权限和外部资源是否仍有效。线程 ID 必须绑定认证用户，不能被任意用户猜测后读取。

## Human-in-the-loop

人工审批适用于付款、删除、对外发送、权限变更等高影响动作。审批界面展示“将执行什么、参数、来源证据、预计影响”，批准后服务端再次校验权限和状态。

```text
Agent 提议动作 → 保存待审批状态 → 人审/改参/拒绝
→ 重新校验 → 幂等执行 → 审计结果
```

审批不应只是模型问一句“确定吗”。必须由可信系统记录审批人、时间和准确动作参数。

## 长期运行

超时、取消、服务重启和重复回调是常态。每个任务有稳定 ID、状态转移、最大执行时间与清理机制。将关键结果持久化，避免进程内存丢失。

## 练习

设计“自动起草采购邮件，审批后发送”的流程；说明审批前后内容能否修改、重复点击会发生什么、发送成功但保存状态失败如何处理。
