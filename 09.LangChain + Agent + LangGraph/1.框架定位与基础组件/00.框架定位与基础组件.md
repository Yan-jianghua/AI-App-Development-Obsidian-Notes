# 框架定位与基础组件

## 先画清数据流

```text
输入 → 模板/上下文 → 模型 → 输出解析/校验
                ↘ 检索器/工具 ↗
```

组件化的价值是可替换模型、统一调用接口、连接检索器和追踪执行过程；代价是依赖版本与隐式行为。能用十几行清晰 Python 完成的确定性流程，没有必要套复杂 Agent。

## 常见组件

- Chat model：向模型发消息并接收响应。
- Prompt template：把变量填入提示；变量始终要校验与转义。
- Retriever：根据问题取回文档，不等于数据库授权层。
- Tool：定义模型可请求的操作与参数模式。
- Output parser：把输出转换为程序对象，仍需错误处理。
- Callback/trace：记录链路、耗时、用量与失败点。

## LCEL 思路

LangChain 表达“输入流经多个组件”的组合。读链时逐步确认每一步输入输出类型、错误传播和同步/异步行为。不要只看最终字符串；查看中间检索结果和模型调用参数。

## 选框架前的判断

1. 是否需要多个可替换供应商或检索实现？
2. 是否有条件分支、循环或工具调用？
3. 是否需要可观测、恢复执行与人工审批？
4. 团队能否承担版本升级和抽象学习成本？

## 练习

分别用纯 Python 函数和 LangChain 组件实现“问答前先检索”的流程，比较代码量、可测试性、追踪能力与依赖复杂度。
