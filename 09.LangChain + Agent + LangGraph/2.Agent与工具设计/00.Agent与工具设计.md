# Agent 与工具设计

## Agent 是什么

Agent 在目标与可用工具之间选择下一步动作，并根据结果继续或结束。它适合步骤难以事先完全固定的问题；固定流程应优先使用显式代码，更容易保证成本和正确性。

```text
观察输入 → 决定是否调用工具 → 校验/执行 → 观察结果 → 再决策 → 完成
```

## 工具契约

每个工具要写清用途、参数类型、权限、副作用、超时和返回错误。读工具与写工具分开；写操作必须审计，可要求人工批准。

```python
def get_order_status(order_id: str, user_id: str) -> dict:
    """查询当前用户可访问订单的状态；不返回支付凭证。"""
    order = repository.get(order_id)
    if order is None or order.user_id != user_id:
        raise OrderNotFound()
    return {"order_id": order.id, "status": order.status}
```

`user_id` 应来自可信认证上下文，不由模型自由填写。模型给出的参数要经过类型、范围和权限检查。

## 循环边界

设置最大步骤数、最大工具调用、总时限、Token/费用预算和每个工具的并发上限。工具失败后决定重试、换策略或停止；不能无休止重新询问模型。

## 多 Agent

多个专门角色可能改善复杂分工，但会增加消息传递、权限、成本和调试难度。先证明单 Agent 的具体瓶颈，再添加明确的子任务边界和验收标准。不要让多个 Agent 互相复述而没有外部可验证结果。

## 练习

设计一个客服 Agent，可查询订单但取消订单必须人工确认。画出正常、订单不存在、权限不足、工具超时、用户拒绝确认五条路径。
