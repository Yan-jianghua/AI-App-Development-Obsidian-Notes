# LangGraph 状态与工作流

## 图的三个概念

- **State**：节点共享的明确数据结构，例如消息、当前步骤、候选证据和错误。
- **Node**：读取状态并返回部分更新的函数。
- **Edge**：决定下一个节点；条件边依据状态选择分支。

```text
START → 检索 → 质量判断 ─足够→ 生成 → 校验 → END
                       └不足→ 改写查询 → 检索（有次数上限）
```

状态字段要避免把敏感信息与巨大原文永久复制。节点尽量幂等，使失败重试不会重复扣款或发消息。

## 什么时候用图

有多分支、循环、人工审批、长时间运行或失败后恢复时，图结构能把控制流显式化。LangGraph 官方定位是有状态编排运行时，强调持久化、流式与人工介入；具体 API 以 [官方概览](https://docs.langchain.com/oss/python/langgraph/overview) 为准。

## 状态设计

```python
from typing import TypedDict

class FlowState(TypedDict):
    question: str
    evidence: list[str]
    answer: str | None
    attempts: int
```

节点只更新它负责的字段。遇到并行分支时定义合并规则；否则两个节点同时写同一字段会产生不确定结果。

## 失败恢复

持久化检查点允许流程继续，但外部副作用不能简单重放。调用外部写工具前生成业务幂等键，并保存调用状态；恢复时先查是否已完成。
