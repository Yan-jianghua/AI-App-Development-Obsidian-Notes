# HTTP、FastAPI 与数据库面试题

## HTTP 与 API

**1. 401 与 403？** 401 表示缺少有效认证，403 表示已识别但权限不足。对象存在性敏感时可统一 404。

**2. 幂等是什么？** 相同请求执行多次的最终状态等价。GET/PUT/DELETE 常按幂等语义设计，支付 POST 则需业务幂等键防重复扣款。

**3. CORS 能保护后端吗？** CORS 限制浏览器跨源读取，脚本和服务端客户端不受同样限制；后端仍必须认证、授权和限流。

**4. 如何设计分页？** 小数据可 offset/limit；大数据和频繁插入优先稳定排序键的游标分页。限制页大小，明确下一页游标和过滤条件。

## FastAPI

**5. `def` 与 `async def` 如何选？** 异步 I/O 库配 `async def`；阻塞库可用普通 `def` 或迁移。CPU 任务移出请求线程/事件循环。

**6. 依赖注入作用？** 声明数据库会话、当前用户和服务依赖，统一创建/清理，测试时可覆盖。不要把所有业务都藏在依赖里。

**7. 请求模型和响应模型为什么分开？** 可写字段与公开字段不同，分开可防 mass assignment 和敏感信息泄露。

**8. 如何测试 API？** 业务规则用单元测试；路由、校验、状态码用 ASGI 客户端；事务、约束和数据库差异用真实依赖集成测试。

## 数据库与缓存

**9. 事务 ACID？** 原子性、一致性、隔离性、持久性。隔离级别与并发异常仍需具体讨论，不能只背缩写。

**10. 索引为何有代价？** 加快特定查询但占存储、拖慢写入；用实际执行计划和工作负载评估。

**11. N+1 查询？** 加载 N 条主记录后逐条查关联数据，多出 N 次查询；预加载、批量查询或 join 处理。

**12. 缓存与数据库如何保持一致？** 常用更新数据库后失效缓存，接受短暂不一致并配 TTL/补偿；强一致场景绕过缓存或设计更严格协议。

**13. 如何防止超卖？** 数据库条件更新、锁或乐观版本号，检查影响行数；并发测试验证。仅“先查库存再扣减”有竞争窗口。
