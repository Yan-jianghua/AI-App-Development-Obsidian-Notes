# 复杂度与分析方法

## Big O

时间复杂度描述输入规模 `n` 增大时操作次数的增长趋势，空间复杂度描述额外内存增长。常见顺序：`O(1)`、`O(log n)`、`O(n)`、`O(n log n)`、`O(n²)`、`O(2^n)`。常数也重要，但首先避免错误的增长级别。

## 常见推导

```python
for x in items:          # n 次
    print(x)              # O(n)

for i in range(n):
    for j in range(n):    # n × n
        pass               # O(n²)
```

二分查找每次把搜索范围减半，约 `log₂n` 次。递归需要把调用栈计入空间；排序常为 `O(n log n)`，但具体实现和数据特点会影响实际性能。

## 摊还与最坏情况

Python 列表末尾 `append` 通常摊还 `O(1)`，偶尔扩容复制整个数组；`pop(0)` 要移动其余元素，为 `O(n)`。字典/集合平均查找接近 `O(1)`，极端哈希冲突可退化。讨论复杂度时说明平均、最坏或摊还前提。

## 测量与优化

先用测试证明正确，再用 `timeit` 或性能分析器测真实负载。不要因微小输入做过度优化；数据库查询、网络和模型调用往往远大于本地算法开销。
