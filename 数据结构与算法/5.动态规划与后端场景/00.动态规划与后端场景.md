# 动态规划与后端场景

## 核心思想

当大问题由重复子问题构成，并且最优解可由子问题组合时，保存中间结果避免重复计算。步骤是定义状态、转移、初始值和计算顺序。

## 例：最少硬币数

```python
def min_coins(coins: list[int], amount: int) -> int | None:
    dp = [amount + 1] * (amount + 1)
    dp[0] = 0
    for value in range(1, amount + 1):
        for coin in coins:
            if coin > 0 and coin <= value:
                dp[value] = min(dp[value], dp[value - coin] + 1)
    return None if dp[amount] > amount else dp[amount]
```

状态 `dp[x]` 表示凑出金额 x 所需最少硬币数；转移从 `dp[x-coin]` 来。时间 `O(amount × len(coins))`，空间 `O(amount)`。输入规模过大时要评估内存与更合适算法。

## 备忘录与自底向上

递归加缓存（memoization）易按问题定义写，但受递归深度影响；自底向上迭代可控。不是所有重复计算都要用动态规划，缓存失效和状态空间也有成本。

## 后端中的算法思维

- 限流可用滑动窗口或令牌桶。
- 定时任务可用堆或时间轮。
- 依赖执行用拓扑排序。
- 推荐或检索候选的 Top-K 用堆。
- 去重、集合交并与缓存键依赖哈希结构。

算法实现应考虑持久化、并发和分布式一致性；进程内正确不等于多实例正确。

## 练习

写出“每天可做或不做某任务，连续做有额外成本”的状态定义与转移；再解释在真实服务中哪些状态需要数据库保证一致性。
